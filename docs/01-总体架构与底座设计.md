# 01 - Orbment（导力匣）总体架构与底座设计

本文档定义桌面工具箱 **Orbment（导力匣）** 的工程架构、技术选型、模块生命周期、统一原生 UI 窗口模型、数据存储 Schema、对外控制面（IPC / MCP）以及独立数据迁移模块的详细规格。后续任何开发者或 Agent 接手时，均以本文档作为底座实现契约。

---

## 1. 项目定位与核心工程原则

### 1.1 背景与要解决的问题
Windows 日常高频效率工具通常各自常驻后台、各自维护托盘图标与界面运行时（如 WebView2、Qt、.NET、独立大内存索引）。作为动机参考，2026-10-20 在开发者电脑上的一次观测（工作集 / 私有内存，单次快照，不作为性能基准）：
- `Everything.exe`：约 561 MB / 554 MB（另有 Everything 服务进程约 11 MB）。这部分主要是索引本身，大小取决于 Everything 开了哪些索引项。
- 独立截图与贴图常驻进程：约 73 MB / 160 MB
- `SoundSwitch.exe`：约 64 MB / 50 MB（另有音量旋钮 AHK 脚本进程）
- `TrafficMonitor.exe`：约 61 MB / 128 MB（其中包含为读硬件温度加载的 .NET 运行时）
- `EcoPaste.exe`：主进程约 36 MB / 29 MB，另有若干 `msedgewebview2.exe` 子进程（本次未测）

**Orbment** 的目标是将上述工具以及磁盘空间分析（NTFS `$MFT` 高速扫描底座 + 可下钻嵌套树图）、Mem Reduct（内存清理与内存树图可视化）、窗口置顶、屏幕取色、外接显示器硬件亮度调节（DDC/CI）、文件占用解锁、端口占用快查、防休眠开关整合为**单一、统一、尽量低内存占用的原生 Rust 程序**，并为后续“任意界面截图/选中文字快速呼出 LLM 小窗”及“通用热键”预留扩展位置。

### 1.2 七条工程原则
1. **参考开源项目与系统原生机制**：参考上游系统 API、交互细节和配置定义，以 Rust 实现。对 GPL 项目只参考行为与配置格式。截图选区的结构层命中回退改编自 Snow Apps 中 `snow-ui-selector` 的 Apache-2.0 历史版本，见[第三方声明](../THIRD-PARTY-NOTICES.txt)。磁盘与内存空间分析采用 NTFS 记录和可下钻的树图交互；Everything 通过公开 IPC 接入。
2. **独立通用，低用户环境耦合**：软件不得硬编码任何特定机器路径或依赖外部私有数据；所有默认值取原软件出厂默认，不取任何人电脑上的当前设置；支持标准安装目录与便携模式（Portable），静态链接 CRT（`+crt-static`），复制到全新 Windows 10（2004+）/ Windows 11 电脑可直接运行。
3. **保留原工具设置项与可调项**：不按单一用户当前开启的设置去裁剪功能；当前未启用的能力（如长截图、录屏、录音设备切换、告警提示等）也要实现并可在设置中开启。
4. **后台逻辑与 UI 生命周期解耦，未启用不加载，空闲时停止重绘**：模块禁用时不注册钩子、不启动后台线程；模块启用但未打开窗口时，仅运行必要的后台监听（如剪贴板监听），不创建可视 UI 窗口或执行渲染；所有窗口采用**事件驱动按需重绘**（无交互、无动画、无数据变化时 0 帧重绘）；重型界面与重型数据（MFT 文件树、离线 OCR 模型）按需加载、闲置回收。
5. **统一原生图形底座，窗口资源相互隔离**：不用 WebView2 / Electron，不把多个旧程序拼壳；UI 层共享同一个主线程 `D3D11 + Direct2D` 设备，但每个窗口各自独立管理自身的呈现目标（`IDXGISwapChain1` 或 Layered/DC 位图目标）与纹理生命周期，且截图/贴图悬浮窗采用独立于普通设置面板的专用窗口管理路径。
6. **旧数据一次性转换为新格式，迁移模块独立可抛弃**：主程序运行时只读写 Orbment 自有格式（`orbment.db` + `config.toml`），不长期兼容双轨读取；历史数据与旧配置迁移放在独立的 `orbment-importer` 可执行程序中，删除后主程序照常编译（见 §7）。
7. **对外留足接口与 MCP，数据库支持直读**：结构化数据存储在开启 WAL 模式的 SQLite 库中，外部 LLM 或脚本可直接只读查询；所有功能动作通过内部 `ActionBus` 统一注册，并经由本地命名管道（Named Pipe）与 `orbment.exe mcp` 子命令向任意 Agent 暴露标准 MCP 工具。

## 2. 技术栈选型与 Workspace 目录拓扑

### 2.1 核心技术选型
- **工具链与最低系统要求**：Rust（`2024 edition`，目标三元组 `x86_64-pc-windows-msvc`），在 `.cargo/config.toml` 中开启 `target-feature=+crt-static` 静态链接 VC++ 运行库；最低支持 **Windows 10 2004（Build 19041）x64** 及以上（满足 `WDA_EXCLUDEFROMCAPTURE`、WGC 帧池及现代 DXGI/D3D11 接口要求）。
- **Windows 系统绑定**：统一使用官方 `windows` / `windows-sys` crate（Win32、COM、WASAPI、DXGI、Direct2D、DirectWrite、Windows.Graphics.Capture、Windows.Media.Ocr、RestartManager、MonitorConfiguration）。重型系统组件（如 Media Foundation、DXGI Capture）按需延迟加载；检测到 Windows N/KN 版缺失 Media Foundation 时提示安装媒体功能包并回退 GIF/WebP 导出。
- **原生 UI 与图形渲染架构（已定：主线程共享 UI `D3D11 + Direct2D` 设备、每窗口呈现目标独立隔离、事件驱动按需重绘）**：
  - **图形设备共享、单线程 UI 约束与窗口资源隔离**：
    - 主 UI 线程共享唯一一个 UI 渲染用 `ID3D11Device`（开启 `D3D11_CREATE_DEVICE_BGRA_SUPPORT`）、`ID2D1Factory1` / `ID2D1Device` 与 `IDWriteFactory`，放弃 `wgpu`（DX12/Vulkan），避免双图形栈并存。**该共享 UI 设备及其 Immediate Context 仅在主 UI 线程单线程调用**，无需跨线程互斥锁；`orbment-vision` 进行静态/流式窗口捕获或硬件视频编码时，按需创建独立的捕获/编码专用 `ID3D11Device`（流式窗口贴图通过捕获设备的 3 槽位 Staging 纹理读回 CPU 缓冲，再由 UI 线程 `UpdateSubresource` 上传至 UI 设备纹理），停止后立即释放，使捕获/编码与 UI 渲染互不争抢上下文、设备丢失互不波及。
    - **按窗口类型选择最简呈现目标（避免静态窗口占用双缓冲交换链显存）**：交互式面板窗口（`TransientPopupWindow`、`MainHostWindow`）、分屏截图遮罩（`CaptureOverlayWindow`）与实时窗口流贴图持有独立的 `IDXGISwapChain1` + `ID3D11RenderTargetView`；而任务栏子窗口（`TaskbarChildWindow`）、OSD/桌面悬浮窗（`OverlayFloatingWindow`）以及静态桌面贴图（`PinWindow`）使用按需重绘的 `UpdateLayeredWindow` / D2D 位图目标，静态贴图无变化时不持有活动双缓冲交换链。关闭、销毁或因分辨率/DPI 变化重建任意窗口时，仅释放或重建该窗口自身的呈现目标与纹理，不影响其他正在显示的贴图、任务栏子窗口或悬浮窗。
    - **`egui` + Direct2D 同窗组合绘制顺序**：在 `MainHostWindow` 等组合窗口中，同一帧先通过 D3D11 顶点/像素着色器管线将 `egui` 输出的三角网格绘制到 SwapChain 后备缓冲（`ID3D11RenderTargetView`），再通过绑定同一 DXGI Surface 的 `ID2D1DeviceContext`（`ID2D1Bitmap1`）在指定裁剪矩形内绘制 Direct2D 硬件加速画布（如嵌套方块树图），`EndDraw` 后统一 `Present(1, 0)`。
    - **设备丢失恢复**：各 `egui::Context` 共享同一份只读字体字节缓冲（`Arc<[u8]>`），且渲染器在 CPU 侧保留活动纹理副本；`PinWindow` 保留 CPU 原图缓冲（或从 `<DATA_DIR>\media\pins\` 重载）。当收到 `DXGI_ERROR_DEVICE_REMOVED` / `DXGI_ERROR_DEVICE_RESET` 时，由 `orbment-ui` 重建共享 UI `ID3D11Device` 并从 CPU 侧数据恢复当前存活窗口的纹理与目标视图。
    - **内存回落口径**：窗口关闭或闲置超时销毁其呈现目标、UI 视图树和窗口专属纹理后，该窗口占用的显存与私有缓冲立即释放；但共享的 `ID3D11Device`、共享字体字节及显卡驱动自身保留的运行时堆仍在进程中驻留，验收时如实记录回落前后的私有内存（见 03 §9）。
  - **事件驱动按需重绘（Event-Driven Repaint）与共享输入法组件**：
    - 面板层使用即时模式的 `egui`（自写基于共享 D3D11 的网格渲染与输入集成层），同时在 `orbment-ui` 中抽出**独立的 Win32 `IMM32` 中文输入法跟随组件**（处理 `WM_IME_STARTCOMPOSITION` / `WM_IME_COMPOSITION` / `ImmSetCompositionWindow` 候选框定位与 `WM_CHAR`），供路径 A（`egui` 输入框）与路径 B（截图标注文字、箭头双击内联评论框）共同复用。
    - **不跑固定 60fps 的持续重绘循环**：窗口无交互、无动画、无数据变更时，主消息循环阻塞在 `MsgWaitForMultipleObjectsEx` 上，**空闲帧率为 0 FPS**。
    - 仅当收到该窗口的输入事件、存在未结束的过渡动画（按 `repaint_after` 定时唤醒，动画结束立即停表）或后台模块发来数据变更消息（且该窗口当前可见）时，才请求重绘该窗口的下一帧。
  - **两条独立的窗口管理路径**：
    - **路径 A（常驻微窗与常规面板路径）**：任务栏监控子窗口与桌面监控悬浮窗/OSD 使用 Direct2D + DirectWrite 直接绘制；设置中心、剪贴板弹窗、快速搜索框、磁盘/内存嵌套树图面板使用 `egui`（D3D11 通道）+ Direct2D 组合绘制。
    - **路径 B（独立截图遮罩与多实例贴图路径）**：全屏透明截图遮罩、鼠标穿透、多实例置顶贴图窗口、多显示器异构 DPI 像素级映射与普通设置窗口行为差异极大，走独立的原生 Win32 + Direct2D（含系统内置特效 `CLSID_D2D1GaussianBlur`、`CLSID_D2D1Shadow`、`CLSID_D2D1Scale`、`CLSID_D2D1ColorMatrix`）窗口管理路径，不塞进普通 `egui` 面板外壳。
- **持久化与全文检索**：`rusqlite`（主程序启用 `features = ["bundled"]`，内置 SQLite 3 已含 FTS5 与 `tokenize='trigram'` 分词器；`orbment-importer` 额外启用 `backup` feature）+ `toml_edit`（读写 `config.toml` 时保留未知键、注释与节顺序）+ 定长二进制结构（MFT 本地快照）。
- **离线 OCR 双挡位（通过 `orbment-core::OcrEngine` 抽象供剪贴板、视觉、快速提问共用）**：
  - **挡位 1（默认保底，无需额外模型文件，在 `orbment-core` 内置）**：调用系统 `Windows.Media.Ocr` API（Stage 4 剪贴板即可直接调用，即使 `vision` 模块被禁用仍可工作；首次调用时检测系统是否已安装对应语言 OCR 包，缺失时提示安装或切换挡位 2）。
  - **挡位 2（可选高精度离线模型，由 `orbment-vision` 在 Stage 6 注册）**：通过 `ort`（启用 `features = ["load-dynamic"]`，仅在首次使用挡位 2 时动态加载本地 `onnxruntime.dll`，避免进程启动即加载）按需加载本地 RapidOCR（PP-OCRv4 Det + Rec）模型，闲置超时后卸载 Session 释放内存。
- **界面语言（已定）**：第一版只做简体中文。所有界面文字（菜单、设置项名称、提示、通知）从第一天起集中放在语言资源文件里，代码中不直接写死中文字符串；用一个成熟的 Rust 国际化库加载（实现时选定）。以后补英文只需新增一份语言文件。
- **日志**：使用 `tracing`，按天滚动写入 `<DATA_DIR>\logs\`，保留天数可配置；默认只记警告与错误，可在设置中调高级别排查问题。

### 2.2 管理员权限与开机启动（已定）
文件搜索/磁盘分析（读 `$MFT`、USN 日志）、内存清理（`SeProfileSingleProcessPrivilege` 等特权）、强制关闭其他进程的文件句柄、读取其他进程的内存布局、硬件温度（PawnIO 驱动，见 02 模块二）都需要管理员权限。采用的方案：
- **可执行文件清单与启动权限**：
  - `orbment.exe` 的内嵌 Manifest 固定声明：`requestedExecutionLevel level="asInvoker"`、`dpiAwareness = PerMonitorV2`，以及 Windows 10/11 `supportedOS` GUID（`{8e0f7a12-bfb3-4fe8-b9a5-48fd50a15a9a}`，确保任务栏子窗口上的 `WS_EX_LAYERED` 透明色键生效），且 Agent 或脚本拉起 `orbment.exe mcp` / `orbment.exe cli` 子命令时**永不弹出 UAC 窗口**。
  - 双击启动保持调用者的当前权限。若已有主实例，就唤起它；否则持有单实例互斥体并启动。需要管理员权限时，用户可从设置显式请求提权重启。现有开机自启任务仍按任务配置运行；普通权限启动不会为了修复任务主动弹出 UAC。
- **开机自启（计划任务最高权限）**：用户在设置中开启“开机自启”时触发一次授权，创建带“使用最高权限运行”登录触发器的计划任务；之后每次开机由系统直接以管理员身份启动，不再弹窗。每次启动时校验计划任务中的可执行文件路径是否与当前 `orbment.exe` 路径一致（防止便携版移动目录后失效，不一致时提示一键更新）。文档与界面注明：若用户在普通标准账户下用另一管理员账户凭据提权，`%APPDATA%` 会指向该管理员账户目录，此场景推荐使用便携模式（`portable.flag`）。
- **清理**：关闭“开机自启”时删除该计划任务；卸载程序（或便携版设置里的“清除系统痕迹”）删除计划任务、资源管理器右键菜单等写入系统的条目。`DATA_DIR` 中的用户数据默认保留，卸载时询问是否一并删除。
- **UIPI 消息拦截与放行对策**：管理员进程向普通进程往外拖放不受影响；但普通权限进程（如 `explorer.exe` 或再次双击的普通权限 `orbment.exe`）向管理员进程发送窗口消息会被系统 UIPI 拦截。对策：
  1. 在主消息/托盘宿主窗口启动时，调用 `ChangeWindowMessageFilterEx` 显式放行 `RegisterWindowMessageW("TaskbarCreated")` 与 `RegisterWindowMessageW("Orbment.Activate")`，确保 `explorer.exe` 重启后能重新挂载托盘与任务栏子窗口，且普通权限重复启动时能唤起已有管理员实例；
  2. 在接收文件拖放或 Everything IPC 的窗口上，调用 `ChangeWindowMessageFilterEx` 放行 `WM_DROPFILES`、`WM_COPYDATA`、`0x0049`（`WM_COPYGLOBALDATA`）；OLE 富格式拖放（`IDropTarget`）受跨完整性级别 COM 限制，在对应阶段实测后决定交互提示。
- **MCP 与提权的关系**：本地 MCP/CLI 接口默认关闭，启用后的动作以主程序的权限执行。结束进程、关闭他人文件句柄、内存清理、文件解锁等高风险动作仍须在设置中逐项授权。

### 2.3 线程、COM 套间与图形上下文并发规则
- **主 UI 线程（STA，`COINIT_APARTMENTTHREADED`）**：创建并持有所有可视窗口句柄（`HWND`），负责 Win32 消息派发、Shell 拖放以及对共享 UI `ID3D11Device` / `ID2D1Device` 的单线程独占渲染调用。
- **剪贴板监听与读取专用线程（STA，`COINIT_APARTMENTTHREADED`）**：当剪贴板模块处于 `ServiceState::Running` 时，在独立 STA 线程创建隐藏消息窗口（`HWND_MESSAGE`）注册 `AddClipboardFormatListener` 并执行 `OpenClipboard` / `GetClipboardData`、大图 PNG 编码与 `blake3` 哈希计算，避免外部程序延迟渲染（Delayed Rendering）或百兆大图复制阻塞主 UI 线程。
- **低级键鼠钩子专用线程**：`WH_KEYBOARD_LL` / `WH_MOUSE_LL` 挂在独立的专用线程上，该线程只跑最小消息循环和钩子回调；回调内忽略带注入标记（`LLKHF_INJECTED` / `LLMHF_INJECTED`）的合成输入，只做纯内存状态判断与异步消息投递，不在钩子回调内执行进程路径查询、窗口探测或磁盘/锁操作，防止超过系统 `LowLevelHooksTimeout` 被摘除。
- **后台工作线程（MTA，`COINIT_MULTITHREADED`）**：跨进程 UIAutomation 探测、WASAPI 音频枚举与通知、监控采样与温度读取（含耗时 DDC/CI 调节）、NTFS `$MFT` 扫描与 USN 监听、树图 Squarified 布局计算、SQLite 写入、OCR 推理均在各自后台工作线程运行。各线程自行初始化并持有各自的 COM 接口实例，跨线程仅通过通道传递纯数据快照，不跨线程直接传递非 Agile 的 COM 指针。
### 2.4 Workspace 目录与 Crate 拓扑
项目根目录为 `F:\Orbment`，采用 Cargo Workspace 组织，各 Crate 职责与依赖方向严格单向，禁止循环依赖：

```text
F:\Orbment\
├── Cargo.toml                  # Workspace 根配置
├── docs\                       # 架构、模块规格与施工手册文档
│   ├── 01-总体架构与底座设计.md
│   ├── 02-模块功能与设置项对齐规格.md
│   └── 03-分阶段开发路线与施工手册.md
├── crates\
│   ├── orbment-core\           # 核心底座：全量配置模型(toml_edit)、SQLite WAL 连接与迁移、ActionBus、双轨生命周期管理、Named Pipe IPC、系统原生 OCR(挡位1)与纯系统调用小工具(置顶/电源请求防休眠/DDC亮度)
```

## 3. 模块生命周期（后台服务与 UI 解耦）与按需内存控制

### 3.1 后台服务生命周期与 UI 视图生命周期双轨解耦模型
模块的**后台逻辑（监听、采样、热键响应、常驻索引）**与**前台 UI 窗口资源（窗口句柄、SwapChain、视图树、缩略图缓存）**必须彻底解耦，由两个正交的状态维度管理：

```rust
/// 维度一：模块后台服务状态（由用户在设置中心的模块总开关 enabled 及运行环境决定）
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ServiceState {
    /// 模块被禁用：不注册监听器、不挂载热键/钩子、不运行后台任务、不创建任何窗口
    Disabled,
    /// 模块已启用：后台常驻逻辑运行中（如剪贴板监听 WM_CLIPBOARDUPDATE、音频监听热键与设备通知、监控采样），
    /// 但此时可以没有创建任何可视 UI 窗口（UiSurfaceState::Unloaded）
    Running,
    /// 模块因环境限制不可用（如用户拒绝管理员提权而该模块强依赖管理员权限，或系统缺失必要组件），界面展示原因
    Unavailable { reason: &'static str },
}

/// 维度二：模块前台 UI 汇总状态（仅当 ServiceState::Running 时可离开 Unloaded；多窗口模块按存活窗口汇总）
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum UiSurfaceState {
    /// 未加载：当前未创建任何可视面板/贴图窗口、无窗口呈现目标、无 egui 视图树或缩略图纹理
    Unloaded,
    /// 前台可见：当前至少有一个可视窗口处于显示状态，采用事件驱动按需重绘
    Visible,
    /// 隐藏并等待闲置回收：瞬态窗口已关闭/隐藏，后台服务（ServiceState::Running）继续工作；
    /// 仅当存在处于 HiddenIdlePending 的窗口时，由 orbment-ui 按最近到期时间按需挂载一次性 SetTimer（无待回收窗口时停表，保持空闲 0 唤醒），到期后销毁窗口呈现目标、UI 视图与缩略图缓存并顺带执行一次 SQLite PASSIVE checkpoint，退回 Unloaded
    HiddenIdlePending { hidden_at_ms: u64 },
    /// 隐藏但常驻（当用户显式配置 lightweight_mode = false 时）：隐藏窗口但不销毁视图缓存
    HiddenResident,
}

pub trait OrbmentModule {
    fn id(&self) -> &'static str;
    fn service_state(&self) -> ServiceState;
    fn ui_state(&self) -> UiSurfaceState;
    /// 启动模块后台服务（Disabled -> Running/Unavailable）：仅注册热键、后台监听或采样，不创建面板 UI
    fn start_service(&mut self, ctx: &CoreContext) -> anyhow::Result<()>;
    /// 按需打开/显示模块 UI（Unloaded/Hidden* -> Visible）：构造窗口、呈现目标与视图数据
    fn open_ui(&mut self, trigger: ActivateTrigger, ctx: &CoreContext) -> anyhow::Result<()>;
    /// 隐藏或关闭模块 UI（Visible -> HiddenIdlePending/HiddenResident 或直接 Unloaded）：后台服务保持 Running
    fn close_ui(&mut self, ctx: &CoreContext) -> anyhow::Result<()>;
    /// 闲置计时到期（HiddenIdlePending -> Unloaded）：释放该模块的窗口呈现目标、UI 视图与可回收缓存
    fn reclaim_idle_ui_and_cache(&mut self, ctx: &CoreContext) -> anyhow::Result<()>;
    /// 彻底停止并禁用模块（Running -> Disabled）：先销毁全部 UI 资源（回到 Unloaded），再注销所有监听器、热键、钩子与后台任务
    fn stop_service(&mut self, ctx: &CoreContext) -> anyhow::Result<()>;
}
```

**典型模块在双轨模型下的行为对照：**
- **剪贴板模块（`clipboard`）**：启用后 `ServiceState = Running, UiSurfaceState = Unloaded`，剪贴板 STA 线程注册 `AddClipboardFormatListener` 接收 `WM_CLIPBOARDUPDATE` 写库，不创建剪贴板可视窗口；按 `Alt+C` 时 `UiSurfaceState -> Visible` 弹出窗口并绘制列表；关闭窗口（或失去焦点 `WM_ACTIVATE(WA_INACTIVE)`）后进入 `HiddenIdlePending`（期间复制新内容依然实时入库），闲置满 `idle_destroy_seconds`（默认 60 秒）释放 UI 资源回到 `Unloaded`；若用户在设置中心关闭剪贴板模块总开关，则 `stop_service()` 移除监听器并停止剪贴板线程。
- **文件搜索与磁盘分析模块（`file_search` / `disk_analyzer`）与共享 `MftEngine` 引用计数**：各窗口关闭时仅释放该窗口自身的 UI 资源（`UiSurfaceState`）；底层共用的 NTFS 内存树由 `orbment-analyzer::MftEngine` 按**活动消费者引用计数**管理（打开的搜索窗、打开的磁盘分析窗、`file_search` 启用且处于 `Resident` 模式各计 1 份引用；当 `file_search.backend = "EverythingBridge"` 时 `file_search` 不持有 MFT 引用）。仅当引用计数归零时，`MftEngine` 才按驻留策略执行回收：若 `file_search` 未启用或处于 `OnDemandOnly` 模式则立即释放内存树；若为默认的 `SnapshotIncrement` 模式，在引用归零满 `idle_release_seconds`（300 秒）后转存 `mft_snapshot.bin` 并释放索引内存。

### 3.2 按需挂载的全局钩子与监听规则
为防止后台空转消耗 CPU 与内存，Windows 系统级钩子必须遵循**引用计数按需挂载**：
1. **`RegisterHotKey`（系统热键）**：优先用于所有标准 `修饰键 + 普通键` 组合（如 `Alt+C` 呼出剪贴板、`Alt+F` 呼出文件搜索、切换音频设备、截图快捷键、剪贴板 `修饰键+数字` 快捷粘贴）。由系统内核派发 `WM_HOTKEY`，不需要挂钩子。
2. **`WH_KEYBOARD_LL`（低级键盘钩子）**：**仅当**以下任一已启用（`ServiceState::Running`）的功能需要时才在钩子专用线程挂载，引用计数归零时立即 `UnhookWindowsHookEx`：
   - 音频模块开启了“硬件音量旋钮按下（`VK_VOLUME_MUTE`）拦截映射”；
   - 剪贴板模块开启了“接管系统 `Win+V`（`replace_win_v = true`）”；
   - 文件搜索或其他动作的快捷键被用户配置为“双击修饰键（如双击 `Ctrl`）”；
   - 视觉模块开启了“允许单键无修饰符快捷键”，或正在进行“录屏键盘按键可视化”；
   - 通用热键引擎配置了 `RegisterHotKey` 无法表达的物理按键拦截规则。
3. **`WH_MOUSE_LL`（低级鼠标钩子）**：**仅当**以下任一功能处于活动状态时才挂载，引用计数归零立即卸载：
   - 视觉模块已启用且配置了至少一条“全局鼠标快捷操作”（如按住修饰键 + 左/中/右键/侧键 X1/X2 拖拽或双击）；
   - 视觉模块正在进行“长截图滚动监听”或“录屏鼠标点击/轨迹可视化”。
4. **`AddClipboardFormatListener`**：只要剪贴板模块处于 `ServiceState::Running`（无论剪贴板弹窗是 `Unloaded`、`Visible` 还是 `HiddenIdlePending`）即在剪贴板专用 STA 线程的 `HWND_MESSAGE` 窗口上保持注册；仅在剪贴板模块被禁用（`ServiceState::Disabled`）时注销。
### 3.3 快捷键冲突处理
- `RegisterHotKey` 注册失败（组合键已被其他程序或系统占用）时，不得静默失效：启动时汇总所有注册失败的快捷键，用一条托盘通知告知；设置中心对应项标红并显示“被占用”。
- Orbment 内部各模块之间的快捷键重复，在设置中心保存时直接拦下并提示。
- 用户修改快捷键时即时尝试注册，失败则保留原快捷键并提示。
- 低级钩子实现的触发（音量旋钮、全局鼠标手势）不会与其他程序“注册冲突”，但可能与其他也挂钩子的工具同时响应，在设置说明里注明。

## 4. 原生窗口管理体系（双路径、5 类窗口模型）

`orbment-ui` 按窗口行为特征划分为**两条独立管理路径、共 5 类原生窗口**。所有常规 UI 窗口在主线程共享同一个底层 `ID3D11Device` + `ID2D1Device`，但**各自拥有独立的呈现目标与资源生命周期**，且均采用**事件驱动按需重绘（空闲时 0 FPS）**：

| 管理路径 | 窗口类别 | 对应功能场景 | Win32 窗口样式与焦点特征 | 独立呈现目标与渲染策略 |
| :--- | :--- | :--- | :--- | :--- |
| **路径 A：微窗与常规面板** | **1. `TaskbarChildWindow`** | TrafficMonitor 任务栏内嵌监控栏 | 照 TrafficMonitor 的做法（`TaskBarDlg.cpp` / `TaskbarHelper`）：`FindWindow("Shell_TrayWnd")` 取主任务栏，`SetParent` 挂入，按任务栏矩形与方向计算位置；Win11 任务栏图标居中时避免与图标重叠；支持副屏任务栏；嵌入失败时退回置顶浮于任务栏上方。通过 `ChangeWindowMessageFilterEx` 放行并监听 `TaskbarCreated`，在 `explorer.exe` 重启后重新挂载 | 独立 D2D DC/GDI 互操作渲染目标（配合透明色键 `SetLayeredWindowAttributes` 或 `UpdateLayeredWindow`）+ DirectWrite 绘制；仅在采样周期（默认 1000ms）且显示的文本/数值实际变化时重绘 |
| **路径 A：微窗与常规面板** | **2. `OverlayFloatingWindow`** | TrafficMonitor 桌面悬浮窗、SoundSwitch 切换 OSD 横幅、独立取色放大镜、置顶指示边框、录屏键鼠提示层、可选桌面悬浮球 | `WS_POPUP` + `WS_EX_LAYERED \| WS_EX_TOPMOST \| WS_EX_TOOLWINDOW \| WS_EX_NOACTIVATE`；支持动态切换 `WS_EX_TRANSPARENT`（鼠标穿透），支持贴边吸附与全屏应用自动隐藏 | 独立 Layered 位图渲染目标（`UpdateLayeredWindow`）+ Direct2D 绘制；OSD 横幅在倒计时（如 3 秒）结束后立即销毁窗口与渲染目标 |
| **路径 A：微窗与常规面板** | **3. `TransientPopupWindow`** | EcoPaste 剪贴板历史弹窗、快速文件搜索框、快速 LLM 提问小窗 | `WS_POPUP` + `WS_EX_TOPMOST \| WS_EX_TOOLWINDOW`。**照 EcoPaste 的焦点逻辑**：呼出时记录当前前台窗口 `last_active_hwnd`，弹窗激活并接收键盘（方向键、打字搜索、IME 输入、空格预览）；失去焦点（`WM_ACTIVATE(WA_INACTIVE)`）自动隐藏；粘贴时隐藏弹窗、把焦点还给 `last_active_hwnd` 并释放物理按住的修饰键后再发送粘贴 | 独立 `IDXGISwapChain1` + 独立 `egui::Context`（共享 D3D11/D2D 设备与只读字体缓冲）；空闲时 0 重绘；关闭后按 `idle_destroy_seconds` 销毁该窗口 SwapChain、视图与缩略图纹理 |
| **路径 A：微窗与常规面板** | **4. `MainHostWindow`** | 统一设置中心、磁盘空间嵌套树图、Mem Reduct 内存清理与进程树图 | 标准 `WS_OVERLAPPEDWINDOW`（支持 Windows 11 Mica/圆角属性 `DwmSetWindowAttribute`） | 独立 `IDXGISwapChain1` + `egui` 表单（D3D11 通道）+ Direct2D 嵌套矩形树图画布；平时不创建，关闭窗口即销毁该窗口 SwapChain 与 UI 树 |
| **路径 B：独立视觉捕获与贴图路径** | **5. `CaptureAndPinWindows`** | 多屏瞬时截图遮罩（`CaptureOverlayWindow`）与多实例贴图窗口（`PinWindow`） | **专用窗口管理路径（不走 `egui` 面板壳，复用共享 IMM32 输入法组件）**：截图遮罩在 `PER_MONITOR_AWARE_V2` 下为**每台显示器创建一个匹配该屏物理像素与 DPI 的无边框 `HWND`**（选区坐标统一使用虚拟桌面物理像素，避免跨异构 DPI 缩放失真与单纹理尺寸上限）并设 `WDA_EXCLUDEFROMCAPTURE`；每张贴图为独立无边框置顶 `HWND`，独立控制鼠标穿透、滚轮缩放、像素级边缘吸附与 Owner 关系 | 每屏截图遮罩与实时窗口区域贴图使用独立 `IDXGISwapChain1`；静态贴图使用按需重绘的 Layered 位图目标（`UpdateLayeredWindow` 配合 `BLENDFUNCTION` 透明度，避免多张静态贴图常驻双缓冲 SwapChain 耗显存）；关闭单张贴图仅释放该贴图自身的纹理与目标 |
### 4.1 入口精简规范：托盘菜单与设置中心导航（已定）
1. **单一主托盘图标**：默认全程序仅显示 1 个 Orbment 主托盘图标（左键单击默认打开设置与模块控制中心，中键单击动作由 `[app].tray_middle_click_action` 配置，默认切换音频设备或一键清理内存；音频模块的 `audio.switch_icon_mode` / `tooltip_info` 默认作用于主托盘图标的动态样式与悬停提示，且 `memory.tray_icon.enabled` 与 `audio.tray_icon.enabled` 独立附加托盘图标均默认关闭）。
2. **托盘右键菜单“未启用即隐身”**：在设置中被禁用（`enabled = false`）的模块，其对应入口**直接从托盘右键菜单中移除**，不展示灰色不可用项。当模块开启时，右键菜单仅保持扁平的 6 组高频入口：
   - `截图 / 贴图 / 取色`
   - `剪贴板历史`
   - `文件搜索`
   - `磁盘与内存分析（含一键清理内存）`
   - `快捷状态（切换音频设备 / 外接显示器亮度 / 防休眠勾选）`
   - `设置中心...` 与 `退出`
3. **设置中心左侧导航栏直带模块总开关**：设置中心采用左侧模块导航栏 + 右侧配置面板布局；左侧每个模块条目右侧直接放置独立的 `[启用/禁用]` 切换滑块，关闭时立即调用 `stop_service()` 卸载该模块的钩子、线程与内存缓存，并同步精简托盘菜单。

## 5. 统一数据存储与配置文件规范

### 5.1 存储目录布局与便携模式
启动时按以下优先级决定数据根目录 `DATA_DIR`：
1. 若命令行显式传入 `--data-dir <PATH>` 或环境变量 `ORBMENT_DATA_DIR` 已设置，则优先使用指定路径。
2. 若可执行文件同级目录存在 `portable.flag` 文件或 `OrbmentData\` 目录，则进入**便携模式**，`DATA_DIR = <exe_dir>\OrbmentData`。
3. 默认标准路径：`%APPDATA%\Orbment`。

`DATA_DIR` 下的文件结构固定如下：
```text
<DATA_DIR>\
├── config.toml                 # 全局与各模块统一配置文件（明文可读、原子写入）
├── orbment.db                  # 核心 SQLite 数据库（开启 WAL 模式，外部 LLM 可直接只读连接）
├── orbment.db-wal              # SQLite WAL 日志
├── orbment.db-shm              # SQLite 共享内存索引
```

### 5.2 SQLite 数据库（`orbment.db`）完整建表 Schema
数据库连接初始化时执行：
```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
PRAGMA journal_size_limit = 67108864; -- 限制 WAL 文件上限为 64 MB
```
随后读取 `PRAGMA user_version;`：若低于当前程序目标 Schema 版本（初始版本为 `1`），则在单个事务内按版本号顺序执行建表/演进脚本并写入新的 `PRAGMA user_version`。开启 `WAL` 后，Orbment 主进程在后台写入剪贴板或监控数据时，外部 Agent / LLM 或脚本可以直接以只读模式（`mode=ro`）打开 `orbment.db` 执行任意 SQL 查询，读写互不阻塞，取代旧的专用读库 MCP。

> **敏感条目（已定）**：剪贴板识别出的 API Key、私钥等敏感内容照常**存原文**，只标记 `is_sensitive = 1`，在界面中按设置打码显示。数据库对外开放直读，直读者能看到原文，这是知情的取舍。

核心表结构定义如下（所有时间戳字段统一存储为带 `Z` 的 UTC ISO-8601 字符串 `YYYY-MM-DDTHH:MM:SS.sssZ`，唯独 `traffic_daily_history.day_date` 按本地自然日 `YYYY-MM-DD` 汇总；删除或过期清理记录时，检查 `content_hash` / `image_rel_path` 无其他记录引用后同步删除 `media\` 下的对应文件）：
```sql
-- 1. 剪贴板自定义分组表（对齐新版 EcoPaste clipboard_groups）
CREATE TABLE IF NOT EXISTS clipboard_groups (
    id          TEXT    PRIMARY KEY,
    name        TEXT    NOT NULL,
    icon        TEXT    NOT NULL,
    is_hidden   INTEGER NOT NULL DEFAULT 0,
    sort_order  INTEGER NOT NULL DEFAULT 0,
    created_at  TEXT    NOT NULL,
    updated_at  TEXT    NOT NULL
);

-- 2. 剪贴板来源应用表（记录复制时的前台进程名与图标）
CREATE TABLE IF NOT EXISTS clipboard_apps (
    id          TEXT    PRIMARY KEY,
    name        TEXT    NOT NULL,
    bundle_or_exe TEXT    UNIQUE COLLATE NOCASE, -- 可执行文件名或规范化路径（大小写不敏感唯一）
    icon_file   TEXT,
    platform    TEXT    NOT NULL DEFAULT 'windows',
    created_at  TEXT    NOT NULL,
    updated_at  TEXT    NOT NULL
);

-- 3. 剪贴板条目主表
-- seq 是显式整数主键，供 FTS5 外部内容表做稳定映射。
-- 不能用隐式 rowid：没有 INTEGER PRIMARY KEY 的表在 VACUUM 时 rowid 可能被重排，索引会对不上记录。
CREATE TABLE IF NOT EXISTS clipboard_items (
    seq           INTEGER PRIMARY KEY,
    id            TEXT    NOT NULL UNIQUE,
    kind          TEXT    NOT NULL, -- 'text' | 'image' | 'files'
    sub_kind      TEXT,             -- 'plain' | 'html' | 'rtf' | 'color' | 'url' | 'email' | 'code' | 'path'
    group_id      TEXT    REFERENCES clipboard_groups(id) ON DELETE SET NULL,
    source_app_id TEXT    REFERENCES clipboard_apps(id)   ON DELETE SET NULL,
    content       TEXT    NOT NULL, -- 文本内容、图片相对路径或 JSON 文件路径数组
    raw_payload   BLOB,             -- 当 kind='text' 且 sub_kind='html'|'rtf' 时无损保存原始 CF_HTML/RTF 字节流，content 存纯文本或主展示内容
    content_hash  TEXT    NOT NULL, -- blake3(kind + ":" + canonical_content)
    search_text   TEXT,             -- 供全文检索的归一化文本（含图片 OCR 提取出的文本；入库时截断至前 64 KB 以防巨型文本撑爆 trigram 索引）
    summary       TEXT,             -- 列表卡片展示摘要
    file_types    TEXT,             -- 文件条目对应的扩展名集合 JSON
    size          INTEGER,          -- 文本条目的 UTF-16 码元长度，或图片/文件条目的总字节数（由 kind 区分语义）
    width         INTEGER,          -- 图片宽度（px）
    height        INTEGER,          -- 图片高度（px）
    use_count     INTEGER NOT NULL DEFAULT 1,
    is_favorite   INTEGER NOT NULL DEFAULT 0,
    is_pinned     INTEGER NOT NULL DEFAULT 0,
    is_sensitive  INTEGER NOT NULL DEFAULT 0,
    platform      TEXT    NOT NULL DEFAULT 'windows',
    note          TEXT,
    created_at    TEXT    NOT NULL, -- ISO-8601 时间戳
    updated_at    TEXT    NOT NULL,
    CHECK (kind <> 'files' OR trim(content) <> '')
);

CREATE INDEX IF NOT EXISTS idx_clipboard_items_updated_at ON clipboard_items(is_pinned DESC, updated_at DESC);
CREATE INDEX IF NOT EXISTS idx_clipboard_items_kind_group ON clipboard_items(kind, group_id, is_favorite);
CREATE INDEX IF NOT EXISTS idx_clipboard_items_hash       ON clipboard_items(content_hash);

-- 4. 剪贴板 FTS5 Trigram 全文索引虚拟表（3 个字符及以上的中英文子串走索引；1~2 字符的短词回退为 LIKE/INSTR 扫描）
CREATE VIRTUAL TABLE IF NOT EXISTS clipboard_items_fts USING fts5(
    search_text,
    note,
    content='clipboard_items',
    content_rowid='seq',
    tokenize='trigram'
);

-- 保持 FTS5 索引自动同步的触发器
CREATE TRIGGER IF NOT EXISTS trg_clipboard_items_ai AFTER INSERT ON clipboard_items BEGIN
    INSERT INTO clipboard_items_fts(rowid, search_text, note) VALUES (new.seq, new.search_text, new.note);
END;
CREATE TRIGGER IF NOT EXISTS trg_clipboard_items_ad AFTER DELETE ON clipboard_items BEGIN
    INSERT INTO clipboard_items_fts(clipboard_items_fts, rowid, search_text, note) VALUES ('delete', old.seq, old.search_text, old.note);
END;
-- 只在被索引的列变化时重建索引行；use_count、updated_at 等频繁更新的字段不触发
CREATE TRIGGER IF NOT EXISTS trg_clipboard_items_au AFTER UPDATE OF search_text, note ON clipboard_items BEGIN
    INSERT INTO clipboard_items_fts(clipboard_items_fts, rowid, search_text, note) VALUES ('delete', old.seq, old.search_text, old.note);
    INSERT INTO clipboard_items_fts(rowid, search_text, note) VALUES (new.seq, new.search_text, new.note);
END;

-- 5. 文件类型图标缓存表
CREATE TABLE IF NOT EXISTS file_type_icons (
    cache_key   TEXT NOT NULL,
    platform    TEXT NOT NULL DEFAULT 'windows',
    icon_file   TEXT NOT NULL,
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL,
    PRIMARY KEY (cache_key, platform)
);

-- 6. 每日网络流量统计表（对标 TrafficMonitor history_traffic.dat）
CREATE TABLE IF NOT EXISTS traffic_daily_history (
    day_date       TEXT    PRIMARY KEY, -- 本地自然日 'YYYY-MM-DD'
    upload_bytes   INTEGER NOT NULL DEFAULT 0,
    download_bytes INTEGER NOT NULL DEFAULT 0,
    adapter_mode   TEXT    NOT NULL DEFAULT 'auto',
    updated_at     TEXT    NOT NULL
);

-- 7. 贴图与历史截图记录表（支持未关闭贴图恢复与历史贴图管理）
CREATE TABLE IF NOT EXISTS pin_records (
    id              TEXT    PRIMARY KEY,
    pin_kind        TEXT    NOT NULL, -- 'image' | 'text' | 'color' | 'window_roi' | 'long_shot'
    group_name      TEXT    NOT NULL DEFAULT 'default',
    title           TEXT,
    image_rel_path  TEXT,             -- media/pins/ 下的图片路径
    text_content    TEXT,
    annotations_json TEXT,            -- 矢量标注图层 JSON（支持二次编辑）
    monitor_name    TEXT,             -- 所在显示器设备名（如 '\\.\DISPLAY1'），配合 monitor_dpi 用于跨屏/改分辨率后位置恢复
    monitor_dpi     INTEGER NOT NULL DEFAULT 96,
    pos_x           INTEGER NOT NULL,
    pos_y           INTEGER NOT NULL,
    width           INTEGER NOT NULL,
    height          INTEGER NOT NULL,
    scale_pct       REAL    NOT NULL DEFAULT 100.0,
    opacity_pct     REAL    NOT NULL DEFAULT 100.0,
    is_topmost      INTEGER NOT NULL DEFAULT 1,
    is_locked       INTEGER NOT NULL DEFAULT 0,
    is_penetrate    INTEGER NOT NULL DEFAULT 0,
    is_thumbnail    INTEGER NOT NULL DEFAULT 0,
    is_active_pin   INTEGER NOT NULL DEFAULT 1, -- 1=当前桌面未关闭贴图，0=已关闭进入历史记录
    created_at      TEXT    NOT NULL,
    closed_at       TEXT
);

-- 8. 文件搜索打开频次历史表（对标 Everything Run History.csv，用于搜索排序加权）
CREATE TABLE IF NOT EXISTS file_run_history (
    full_path     TEXT    PRIMARY KEY COLLATE NOCASE,
    run_count     INTEGER NOT NULL DEFAULT 1,
    last_run_date TEXT    NOT NULL
);
```

### 5.3 MFT 本地紧凑快照格式（`cache/mft_snapshot.bin`）
为支撑文件搜索模块的三挡驻留策略（特别是默认的**“闲置释放 + 本地快照 USN 增量唤醒”**），内存中的文件树在序列化到 `mft_snapshot.bin` 时采用显式填充对齐的小端（Little-Endian）定长二进制布局，并通过写临时文件 + 原子 `ReplaceFileW`/`rename` 提交（读取时仅校验魔数、版本号及 `文件总字节数 == 48 + volume_count*48 + total_nodes*48 + string_pool_bytes` 的 `O(1)` 长度一致性，不对百兆缓存做全文件哈希计算）：
- **Header（严格 48 字节）**：
  - `0..8`：魔数 `ORBMFT01`（`[u8; 8]`）
  - `8..12`：格式版本号 `version: u32`（当前为 `1`，版本或文件长度不匹配时直接丢弃快照重扫）
  - `12..16`：卷数量 `volume_count: u32`
  - `16..24`：总节点数 `total_nodes: u64`
  - `24..32`：字符串池总字节数 `string_pool_bytes: u64`
  - `32..40`：写入时间戳 `written_at_unix_ms: u64`
  - `40..48`：显式保留字段 `reserved: u64`（填 0）
- **Volume Table（严格每卷 48 字节）**：
  - `0..8`：卷序列号 `volume_serial: u64`
  - `8..16`：`usn_journal_id: u64`
  - `16..24`：`last_usn: i64`（用于唤醒时调用 `FSCTL_READ_USN_JOURNAL` 仅拉取增量变更；若 Journal ID 变化或 `last_usn` 已被系统截断返回 `ERROR_JOURNAL_ENTRY_DELETED`，则自动回退整卷重扫）
  - `24..32`：卷根目录 FRN `root_frn: u64`
  - `32..36`：节点起始下标 `first_node_index: u32`
  - `36..40`：节点数量 `node_count: u32`
  - `40..42`：盘符 `drive_letter: u16`（如 `'C'`；无盘符挂载卷填 `0`）
  - `42..44`：卷属性标志 `flags: u16`
  - `44..48`：显式对齐填充 `reserved: u32`（填 0；卷身份由 `volume_serial` 唯一标识，无盘符挂载卷路径在运行时解析）
- **Node Array（严格每节点 48 字节定长，8 字节字段在前自然对齐）**：
  - `0..8`：`file_ref_number: u64`（低 48 位 MFT Record 号，高 16 位 Sequence 号）
  - `8..16`：`logical_size: u64`（逻辑大小，字节）
  - `16..24`：`allocated_size: u64`（实际磁盘分配大小，支持压缩/稀疏文件；磁盘分析默认按它统计）
  - `24..32`：`modified_time_ns100: i64`（Windows `FILETIME` 100ns 精度时间戳，无损保留 NTFS 时间范围与精度）
  - `32..36`：`parent_index: u32`（父目录在 Node Array 中的下标；卷根目录的 `parent_index` 固定为 `u32::MAX` 哨兵）
  - `36..40`：`name_offset: u32`（文件名在字符串池中的字节起点）
  - `40..42`：`name_len: u16`（文件名字节数）
  - `42..44`：`flags: u16`（目录位、隐藏位、系统位、硬链接位、重解析点/符号链接位）
  - `44..48`：显式对齐填充 `reserved: u32`（填 0）
- **String Pool（UTF-8 字节流）**：所有文件名连续存储为标准 UTF-8 字节流（极罕见的非法 UTF-16 代理项直接 `from_utf16_lossy` 处理，不引入额外自定义编码层）。
- **硬链接、重解析点与搜索/磁盘分析过滤边界**：硬链接（同一 MFT 记录拥有多个 `$FILE_NAME` 属性）在搜索索引中按每个路径名一个节点存储（运行时 `FRN -> 小标` 映射支持一对多，以便 USN 更新同步所有硬链接路径）；但在**汇总目录或全盘占用空间、以及大文件/重复文件统计时，必须按同卷低 48 位 MFT Record 号去重**，同一物理文件仅计入一次大小，且不将指向同一 MFT 记录的硬链接误报为可释放的重复文件；目录符号链接/Junction（重解析点）默认不递归跨越统计。`file_search.included_drives` / `exclude_paths` 仅作用于文件搜索结果过滤，磁盘空间分析始终完整扫描所选目标卷以确保目录大小准确。

> **内存估算（未实测）**：快照定长节点 48 字节 + 平均文件名约 24 字节 + 运行时树邻接/FRN 映射约 24~32 字节 ≈ 96~104 字节/文件，200 万文件运行时约 190~210 MB。闲置释放后从快照恢复并追平 USN 的耗时以实测为准。

## 6. 对外控制面、Named Pipe IPC 与 MCP 架构

### 6.1 统一内部动作总线（`ActionBus`）
所有模块的业务动作不仅绑定给 UI 按钮或全局快捷键，必须同时注册到 `orbment-core::action_bus::ActionBus`。这使得：
1. 全局快捷键触发动作；
2. 命令行 `orbment.exe cli <action> [args]` 触发动作；
3. 外部 Agent 通过 `orbment.exe mcp` 触发动作；
4. 未来内置的“快速 LLM 提问小窗”通过 Function Calling 操控工具箱；
**以上四者走同一套代码路径与参数校验，不重复写两套逻辑。**

动作在 `ActionBus` 内部与配置文件、CLI 中统一用 `<模块ID>.<动作>` 的小写点分命名（前缀严格对应 §5.1.1 的模块 ID，如 `audio.switch_playback`、`audio.switch_recording`、`audio.toggle_mic_mute`）；在向 MCP 与 LLM Tool Calling 暴露时，由于 OpenAI / Anthropic 工具名仅允许 `[a-zA-Z0-9_-]`，在协议适配层单点将 `.` 双向映射为 `_`（如 `audio_switch_playback`）。

### 6.2 本地命名管道（Named Pipe）、跨完整性级别通信与 MCP 权限边界
只有开启 MCP/CLI 接口后，外部 Agent 和终端才能通过本地管道连接主进程。主进程可能由用户显式提权启动，而客户端通常仍以普通权限运行：
1. **单实例互斥体与跨完整性级别本地管道**：
   - 主进程用 `OpenMutexW` 检查现有实例，再用 `CreateMutexW` 持有单实例互斥体；检查成功或返回访问拒绝都表示已有实例运行。
   - 主进程监听本地命名管道 `\\.\pipe\orbment-control-v1`：创建管道时构造显式安全描述符（SDDL），仅向**当前登录用户的用户 SID（`TokenUser`）**授予读写权限（避免管理员令牌默认 DACL 将所有者设为 Administrators 组导致同用户非提权进程被拒），显式设置**中等完整性级别标签（Medium Mandatory Label，`S:(ML;;NW;;;ME)`）**，并开启 `PIPE_REJECT_REMOTE_CLIENTS`，使同一登录会话下的普通权限 `orbment.exe mcp` / `cli` 能正常读写该管道，同时拒绝其他账户与远程连接。
2. **`orbment.exe mcp` / `cli` 无状态不提权转发**：当以 `mcp` 或 `cli` 子命令启动时（依赖 `asInvoker` 清单），子进程**不请求 UAC 提权、不初始化任何 UI 或钩子、不加载图形/OCR 重型 DLL**，仅作为纯客户端连接主进程命名管道；若主进程未运行则直接返回明确错误，不自动后台拉起主进程。
3. **简单直接的 MCP 权限边界**：标 ⚠ 的高风险工具默认关闭（对应 `[mcp]` 的 `allow_*` 开关），需用户在设置中心手动勾选开启；`app.config_set` 拒绝修改受保护配置项（包括 `[mcp]` 权限开关本身、`[app].autostart`、`[quick_ask]` 接口地址与模型、`[hotkey_engine]` 外部命令规则、所有外部可执行命令路径，以及未获 `allow_memory_clean` 授权时的 `memory.auto_clean_*` 开关），防止外部 Agent 直接或间接自开权限，其余不做冗余校验。

## 7. 独立可拆卸的数据迁移模块（`orbment-importer`）设计

### 7.1 架构隔离与并发互斥原则
- `orbment-importer` 单独编译为 `orbment-importer.exe`（清单同样为 `asInvoker`）。它仅复用 `orbment-core` 的配置结构与建库定义，**`orbment-app` 及任何运行时 crate 都不得依赖 `orbment-importer`**，主程序也不提供 `import` 子命令。
- **与主程序互斥运行（防配置与写库冲突，且不误建互斥体）**：`orbment-importer` 启动时首先调用 `OpenMutexW(SYNCHRONIZE, FALSE, L"Local\\Orbment_SingleInstance")`（绝不调用 `CreateMutexW`，避免导入期间占用主程序互斥体）；若成功打开或返回 `ERROR_ACCESS_DENIED`（代表 `orbment.exe` 正在运行），立即提示用户先退出 Orbment 主程序再执行导入，仅当返回 `ERROR_FILE_NOT_FOUND` 时继续执行。
- 迁移操作采用 **“一致性只读备份 → 事务转换写入新库 → 完成后不再读旧库”** 的单向一次性流程，支持 `--source <all|clipboard|audio|monitor|vision|everything>` 按来源选择性导入，以及 `--only-unset-config`（仅填充用户尚未在 Orbment 中修改过的配置项，防止覆盖用户在前期阶段已调好的设置）。
- **SQLite 在线一致性备份（修正三文件裸拷贝风险）**：读取外部 SQLite 数据库（如正在运行的 EcoPaste）时，严禁直接用文件拷贝依次复制 `.db`、`.db-wal`、`.db-shm`（会因并发写入或 WAL checkpoint 产生不一致损坏快照）；必须以只读连接打开源库（设置 `busy_timeout`），调用 **SQLite Online Backup API（`rusqlite::backup::Backup::run_to_completion` 一次性拷贝全部页面）** 在事务级一致性保证下将源库完整备份到临时目录的私有快照文件中，再从私有快照读取转换；若源库被独占锁死则明确提示用户先退出原软件后重试。
- 不再需要迁移功能时，从根 `Cargo.toml` 的 `members` 中删掉 `crates/orbment-importer` 并删除该目录，主程序无需改动即可编译。

### 7.2 源数据定位规则
- importer 中**不写死任何具体电脑上的路径**。每种来源先按标准位置自动查找（如 `%APPDATA%\SoundSwitch\`、`%APPDATA%\TrafficMonitor\`、Everything 的 `%APPDATA%\Everything\`），也检查便携模式位置（程序目录旁的配置文件）；找不到或软件装在自定义位置（如自定义了数据目录的 EcoPaste）时，由用户手动选择文件或目录。
- `--dry-run` 先列出找到了哪些来源、各有多少条记录、哪些配置项与当前 `config.toml` 存在冲突、哪些映射不了，确认后再正式写入。

### 7.3 各来源的转换映射规则
| 原软件 | 数据与格式 | 迁移转换规则 |
| :--- | :--- | :--- |
| **EcoPaste（新版，SQLite）** | `db\clipboard.db`（`clipboard_items` + `clipboard_apps` + `clipboard_groups` + `file_type_icons`）及 `config\settings.json` | 逐字段转换为 `orbment.db` 的对应表（字段大体对应，`seq` 等由新库生成，`search_text` 截断至 64 KB），按 `id` / `content_hash` 幂等迁入；外部图片与图标从原目录按内容哈希拷入 `<DATA_DIR>\media\`；`settings.json` 映射到 `config.toml` 的 `[clipboard]` 节 |
| **EcoPaste（旧版 v0.5）** | `EcoPaste.db`（`history` 单表）及 `.store.json` | 将 `history` 中新版库没有的条目按 `content_hash` 去重补齐（`html`/`rtf` 归入 `kind='text', sub_kind='html'|'rtf'`）；新旧配置共存时以新版为准 |
| **SoundSwitch** | `SoundSwitchConfiguration.json` | 映射已选设备 ID、切换模式、热键、OSD 横幅时长/透明度/位置、Profile、应用音频路由规则到 `[audio]` |
| **TrafficMonitor** | `config.ini` 与 `history_traffic.dat`（及 `.bak`） | 解析采样间隔、网卡选择、悬浮窗与任务栏窗口的位置/字体/颜色/显示项/告警阈值写入 `[monitor]`（主板温度相关位与告警项忽略）；合并 `history_traffic.dat` 与 `.bak` 的每日上下行字节数（同日期记录在单文件内求和，跨 `.dat`、`.bak` 以及 `orbment.db` 中已有重叠日期的记录一律按最大值 `MAX` 去重合并，防止并排试用期间双倍累加）写入 `traffic_daily_history` |
| **视觉模块旧配置** | 视觉与右键菜单 JSON 配置文件 | 配置文件中的标注默认参数、录屏帧率、自动保存、快捷键映射到 `[vision]` |
| **Everything** | Everything `Run History.csv` | 将 `Run History.csv` 导入 `file_run_history` 表用于搜索结果排序加权 |

> **不纳入 importer 的**：AutoHotkey 脚本。任意 AHK 脚本无法通用解析；“音量旋钮按下切换播放设备”在 Orbment 设置里开一个开关即可（`[audio.knob_remap]`），由用户自行开启。

## 8. 内部诊断

用于验证“未启用模块不占资源”“闲置后内存回收”这类承诺，也方便排查问题。

- `ModuleManager` 为每个模块记录：当前后台状态（`ServiceState`）与 UI 状态（`UiSurfaceState`）、该模块启动的线程数、已注册的快捷键与钩子引用、最近一次打开 UI 与闲置回收的时间。
- 进程级数据：工作集、私有内存、GDI/User 句柄数、线程总数、当前挂载的低级钩子（键盘/鼠标各几个引用）。
- 查看方式：`orbment.exe cli diag` 输出 JSON；`app.status`（MCP 为 `app_status`）返回同样内容；设置中心“关于/诊断”页显示同一份数据。
- 各阶段合入前的检查（03 §9）以这份诊断数据为准，再用 Process Explorer 交叉核对。
