# 02 - Orbment（导力匣）模块功能与设置项对齐规格

本文档逐模块定义 **Orbment** 需要实现的底层原理、核心交互，以及与原软件对齐的主要设置项。

**读表须知（适用于全文所有设置项表格）：**
1. **表中列出的是主要设置项，不是完整清单。** 带 `.*` 的条目和表里没列出的项，在实现该模块时以原软件为准全量补齐：开源软件对照源码中的配置定义，闭源软件对照其设置界面。原则是原软件有的可调项都保留，不按任何人当前的使用情况裁剪。
2. **“开发者电脑当前值”一列只是迁移验收时的对照参考，不是 Orbment 的默认值。** Orbment 的默认值一律取原软件出厂默认（开源软件以源码为准，闭源软件以全新安装为准），实现时核对填入。
3. 配置键名是 Orbment 自己的命名；“原字段”一列只用于 importer 迁移映射。

## 模块一：音频设备切换与旋钮映射（`orbment-audio`）

### 1.1 对标基准
- **SoundSwitch**（开源 `GPL-3.0`，参考其功能行为与 `%APPDATA%\SoundSwitch\SoundSwitchConfiguration.json` 配置项定义，用 Rust 独立实现）
- **键盘音量旋钮按下映射**（原先用 AutoHotkey 脚本把静音键 `Volume_Mute` 改成切换播放设备，这类旋钮按下时发出的就是静音键）

### 1.2 核心 Windows API 与实现原理
1. **设备枚举与插拔监听**：
   - 使用 WASAPI `IMMDeviceEnumerator::EnumAudioEndpoints(eRender / eCapture, DEVICE_STATE_ACTIVE)` 获取播放与录音设备列表、设备友好名称（`PKEY_Device_FriendlyName`）、设备图标与 USB 属性。
   - 实现 `IMMNotificationClient` COM 回调接口，实时接收设备新增、移除、状态变更与默认设备变更事件，无需后台轮询。
   - 设置页和快捷键使用同一份已选端点。端点 ID 优先；Windows 已不认识旧 ID，且同一方向的旧记录和在线端点按名称唯一对应时，才把勾选迁移到新 ID。已知离线端点和有歧义的旧记录继续保留。
2. **全局默认音频设备切换**：
   - 调用未公开的 `IPolicyConfig` / `IPolicyConfigVista` COM 接口（SoundSwitch 等长期使用，Win7 至 Win11 可用，但属于未公开接口，系统更新后需回归验证）（CLSID `{870af99c-171d-4f9e-af0d-e63df40c2bc9}`）：
     - `SetDefaultEndpoint(deviceId, eConsole)`
     - `SetDefaultEndpoint(deviceId, eMultimedia)`
     - 当开启 `change_communications = true` 时，同步调用 `SetDefaultEndpoint(deviceId, eCommunications)`。
3. **指定前台应用/规则音频路由（Per-App Audio Routing，对齐 SoundSwitch `SwitchForegroundProgram` 与 `AppSoundRules`）**：
   - 通过 `GetForegroundWindow` -> `GetWindowThreadProcessId` 获取当前前台进程 PID，或按 `AppSoundRules` 匹配进程可执行文件路径。
   - 调用 Windows 10/11 音频策略接口 `IAudioPolicyConfigFactory`（`Windows.Media.Internal.AudioPolicyConfig`）的 `SetPersistedDefaultAudioEndpoint(processId, flow, role, deviceIdString)`，实现单进程不改系统全局默认设备的独立音频路由。这是未公开的 WinRT 接口，**不同 Windows 版本的接口 IID 不同**（Win10 21H2 前后不一样），需按系统版本选择，参考 SoundSwitch 源码的处理方式。
4. **音量保持（Keep Volume）与麦克风静音**：
   - 通过 `IAudioEndpointVolume` 读取/设置主音量（`GetMasterVolumeLevelScalar` / `SetMasterVolumeLevelScalar`）与静音状态（`SetMute` / `GetMute`）。
   - 开启“持续静音提醒（`PersistentMuteNotification`）”时，当默认录音设备处于静音状态，在屏幕指定位置保持微型提示图标。
5. **键盘音量旋钮按下拦截（替代 AutoHotkey 脚本）**：
   - 当 `knob_remap.intercept_volume_mute = true` 时，在 `WH_KEYBOARD_LL` 钩子（专用线程，见 01 §2.3）中拦截硬件发出的 `VK_VOLUME_MUTE`（`0xAD`）按下事件（判断 `LLKHF_INJECTED == 0` 仅拦截物理按键，放行软件模拟静音），返回非零吞掉原系统静音行为，并投递动作 `audio.switch_playback`（可在设置中改为其他动作）。**默认关闭**：开启后该键不再静音，必须由用户自己打开。

## 模块二：网速与硬件监控（`orbment-monitor`）

### 2.1 对标基准
- **TrafficMonitor**（开源，参考 `%APPDATA%\TrafficMonitor\config.ini` 与 `history_traffic.dat`）

### 2.2 核心 Windows API 与实现原理
1. **网络流量采样与网卡自动选择**：
   - 调用 `GetIfTable2`（`iphlpapi.dll`）读取各网络接口的 `InOctets` 与 `OutOctets`，按采样周期（默认 `1000ms`）计算瞬时上下行速率，并累加当日总流量写入内存与 `traffic_daily_history` 表。
   - 支持三种网卡选择模式：
     - `auto_select = true`：自动选择当前有流量活动的物理/虚拟主网卡（需兼容 VPN / 代理软件创建的虚拟网卡）；
     - `select_all = true`：汇总所有非环回活动网卡流量；
     - 指定单一网卡名称（`connection_name`）。
2. **CPU、内存、显卡、硬盘使用率与温度后台采样**：
   - 所有采样均在 `orbment-monitor` 后台工作线程执行，采样完成后仅当显示的文本/数值发生变化时通知 UI 线程重绘对应微窗。
   - **CPU 使用率**：支持双算法切换（对应 `get_cpu_usage_by_cpu_times` / `cpu_usage_acquire_method`）：
     - 方法 A（默认，轻量快速）：调用 `GetSystemTimes` 获取 `IdleTime`、`KernelTime`（含 `IdleTime`）与 `UserTime`，按相邻两次采样差值计算：`CPU% = 100.0 * (1.0 - ΔIdle / (ΔKernel + ΔUser))`（首样本或分母为 0 时记 0%）；
     - 方法 B（性能计数器）：通过 PDH（`\Processor(_Total)\% Processor Time`）按核心或总计读取。
   - **物理内存使用率**：调用 `GlobalMemoryStatusEx` 读取 `dwMemoryLoad`、`ullTotalPhys`、`ullAvailPhys`。
   - **GPU 与显存使用率**：通过 D3DKMT（`D3DKMTQueryStatistics`）或缓存的 PDH `\GPU Adapter Memory(*)\Dedicated Usage` 读取**整卡专用显存占用**，通过缓存的 `\GPU Engine(*)\Utilization Percentage` 实例按引擎类型汇总显卡核心占用（仅在进程/适配器变更时刷新计数器列表，避免每秒全量枚举）。
   - **硬盘活动率与速率**：通过 PDH `\PhysicalDisk(_Total)\% Disk Time` 或 `IOCTL_DISK_PERFORMANCE` 获取。
   - **硬件温度与 CPU 频率（已定：单进程纯 Rust 原生读取，不带 `.NET` 助手进程，第一版不做主板温度）**：
     - **显卡温度（纯用户态 API）**：NVIDIA 动态加载系统自带 `nvml.dll`（NVML C 接口），AMD 动态加载 `atiadlxx.dll`（ADL 接口），Intel 调 IGCL/D3DKMT，无需内核驱动。
     - **硬盘温度（Windows 原生 API，低频轮询防唤醒）**：直接对物理磁盘调用 `IOCTL_STORAGE_QUERY_PROPERTY`（`StorageDeviceTemperatureProperty` / `StorageAdapterTemperatureProperty`）及 SMART 接口，覆盖 NVMe 与 SATA 硬盘；温度轮询周期设为每 10~30 秒一次，且通过 `GetDevicePowerState` 跳过已休眠停转的机械硬盘，避免唤醒磁盘。
     - **CPU 频率与温度**：CPU 频率通过系统原生 `CallNtPowerInformation(ProcessorInformation)` 或 PDH 获取；CPU 温度参考 `LibreHardwareMonitor`（`MPL-2.0`）的寄存器定义，在 Rust 中通过 **PawnIO** 驱动读取 Intel MSR（`IA32_PACKAGE_THERM_STATUS` / `IA32_THERM_STATUS`）与 AMD Zen SMU 温度寄存器。
     - **主板温度（已定第一版不做）**：主板 Super I/O 芯片型号繁杂，第一版直接不做主板温度采集（`config.ini` 迁移时忽略主板温度项）。
     - 未勾选任何温度/频率项时，不加载上述 DLL、不打开 PawnIO 驱动句柄。PawnIO 驱动未安装且用户勾选了 CPU 温度时，界面提示并引导安装，其余监控项（网速、CPU/内存/显卡/硬盘占用与显卡/硬盘温度）照常工作。
3. **双窗口形态（桌面悬浮窗 + Windows 任务栏内嵌子窗口）**：
   - **桌面悬浮窗**：支持透明度（`transparency`）、置顶（`always_on_top`）、锁定位置（`lock_window_pos`）、鼠标穿透（`mouse_penetrate`）、超出屏幕边界（`alow_out_of_border`）、全屏程序运行时自动隐藏（`hide_main_wnd_when_fullscreen`，通过 `SHQueryUserNotificationState` 或前台窗口矩形等于显示器矩形判定）以及兼容解析 TrafficMonitor 原生皮肤目录（同时支持旧版 `skin.ini` 与新版 `skin.xml` + 背景图）。
   - **任务栏内嵌窗口**：参考 TrafficMonitor 的 `TaskBarDlg.cpp` / `TaskbarHelper` 机制实现（`Shell_TrayWnd` + `SetParent`，Win11 居中图标避让，副屏任务栏，嵌入失败回退，细节见 01 §4），支持靠左显示（`task_bar_wnd_on_left`）、边缘吸附（`task_bar_wnd_snap`）、独立背景色/透明色（`task_bar_back_color` / `transparent_color`）及状态条颜色（`status_bar_color`）。
4. **不做（已定）**：TrafficMonitor 的第三方 DLL 插件接口不兼容；主板温度第一版不做。

## 模块三：内存清理、进程内存树图可视化与端口快查（`[memory]`，`orbment-analyzer::memory`）

### 3.1 对标基准
- **Mem Reduct**（开源 `GPL-3.0`，参考其公开的内存清理系统调用与设置界面定义，用 Rust 独立实现）
- **可下钻嵌套内存树图（Memory Nested Treemap，与模块五磁盘分析共用同一套后台 Squarified 布局计算 + Direct2D 嵌套树图绘制组件）** + **端口占用快查杀进程** + **残留进程清理**
### 3.2 核心 Windows API 与实现原理
1. **底层系统内存清理（对齐 Mem Reduct 6 大清理区域）**：
   - 运行时动态请求 `SeProfileSingleProcessPrivilege` 与 `SeIncreaseQuotaPrivilege` 权限（若当前非管理员运行，在 UI 与返回结果中明确提示 `需要管理员权限（076）`，点击“一键提权”时按 01 §2.2 以管理员身份重启 `orbment.exe`）。
   - 调用 `ntdll.dll` 的 `NtSetSystemInformation`（或 `EmptyWorkingSet` 遍历进程）：
     - **工作集（Working Set）**：`SystemMemoryListInformation` -> `MemoryEmptyWorkingSets (2)`；
     - **系统工作集（System Working Set / File Cache）**：`SystemFileCacheInformationEx` 将最小/最大缓存集短暂收缩；
     - **备用页面列表（Standby List）**：`MemoryPurgeStandbyList (4)`；
     - **低优先级备用列表（Standby List Priority 0）**：`MemoryPurgeLowPriorityStandbyList (5)`；
     - **已修改页面列表（Modified Page List）**：`MemoryFlushModifiedList (3)`；
     - **合并内存页面列表（Combine Memory Lists，Win10+）**：`SystemCombinePhysicalMemoryInformation (130)`。
     - 以上区域列表以 Mem Reduct 源码（GitHub `henrypp/memreduct`）为准核对；新版 Mem Reduct 可能还有“注册表缓存”等清理项，实现时按源码补齐。表中的词条编号只用于对照它的设置界面，依据是源码，不是语言包。
   - **防卡死保护（对齐 Mem Reduct 073 警告）**：勾选“备用内存”与“已修改内存”时，首次启用弹出明确提示（`可能导致清理时电脑短暂卡顿，可勾选不再提示`），清理在独立工作线程执行并计算清理前后释放的物理内存差值。
2. **可下钻嵌套内存树图（Memory Nested Treemap，与磁盘树图共用组件）**：
   - **第一层（系统全局物理内存概览，近似分项）**：基于 `SystemMemoryListInformation` 与 `GlobalMemoryStatusEx` 将物理内存划分为：**进程工作集汇总**、**系统缓存/备用列表（Standby/Modified）**、**内核池（Paged/NonPaged Pool）**、**空闲内存（Free）**，界面标明“近似概览”。
   - **第二层（按进程家族嵌套方块）**：枚举活动进程的 `PrivateUsage`（Commit Size）与 `WorkingSetSize`；自动将多进程应用（如 `msedgewebview2.exe`、`chrome.exe`、`svchost.exe`）按父子或同名进程聚合成**带标题栏外框容器**，内部嵌套各子进程方块，支持 `+ / -` 调节展开层级深度。
   - **第三层（双击下钻单进程内部虚拟内存）**：双击任一进程方块后，通过 `VirtualQueryEx` 扫描该进程地址空间，按 **Image（加载的 `.dll`/`.exe` 模块）**、**Mapped File（内存映射文件）**、**Private Commit（私有提交内存，如堆/栈/匿名分配）** 画出内部嵌套树图（对受保护系统进程无法打开句柄时直接显示不可访问提示）。
3. **端口占用快查与一键杀进程**：
   - 调用 `GetExtendedTcpTable`（`TCP_TABLE_OWNER_PID_ALL`，IPv4 + IPv6）与 `GetExtendedUdpTable`（`UDP_TABLE_OWNER_PID`，IPv4 + IPv6），建立 `本地端口 -> (协议, 状态, PID, 进程名, 完整路径, 命令行)` 映射。
   - 支持在内存面板或统一搜索框输入 `:端口号`（如 `:3000`、`:8080`）直接列出占用进程，提供“一键结束进程（`TerminateProcess`）”“定位文件”“复制命令行”操作。
4. **残留进程清理（新增能力，无对标软件）**：
   - **解决的问题**：主程序关掉后，它拉起的帮手进程（WebView2 子进程、更新程序、崩溃上报、编辑器拉起的 node / 语言服务器等）仍留在后台占内存。与内存清理不同，这里是真正结束无用进程，内存不会再被占回去。
   - **家族登记**：用户登记“进程家族”：主程序（owner）可执行文件名（可选绑定路径前缀）、帮手（companion）可执行文件名、豁免列表、是否连同帮手的子进程一起处理。可在内存树图里对某个进程家族色块右键“登记为家族”，从当前进程关系预填。
   - **判定**：当已能枚举到的进程中**该家族所有主程序均不在运行**、而帮手进程仍在运行时，列为“疑似残留”（校验进程创建时间不早于父进程以防 PID 复用；系统进程 PID ≤ 4 与 Orbment 自身永远排除）。
   - **执行**：从不自动结束。在内存面板列出预览，用户点击确认后执行礼貌关闭（`WM_CLOSE`）或单独确认的强制结束（`TerminateProcess`）。
   - 在内存树图中，被判为残留的家族色块标题栏直接标出“主程序已退出，剩余 N 个进程”。

## 模块四：剪贴板历史（`orbment-clipboard`）

### 4.1 对标基准
- **新版 EcoPaste**（SQLite 存储，配置在 `settings.json`）的功能与设置项；旧版 EcoPaste v0.5 的设置（`.store.json`）中新版没有的能力一并参考。

### 4.2 核心 Windows API 与实现原理
1. **事件驱动捕获与多格式优先级解析**：
   - 在剪贴板专用 STA 线程的隐藏消息窗口（`HWND_MESSAGE`）上通过 `AddClipboardFormatListener` 监听 `WM_CLIPBOARDUPDATE`，剪贴板读取、大图 PNG 编码与哈希均在该线程或后台工作线程完成，不阻塞主 UI 线程。
   - 捕获时同时通过 `GetForegroundWindow` -> `GetWindowThreadProcessId` -> `QueryFullProcessImageNameW` 获取来源应用名称与图标（存入 `clipboard_apps` 表）；若来源进程在 `filters.excluded_app_ids` 排除列表中则直接忽略。
   - 同时检查 Windows 剪贴板隐私标记格式（`ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory`、`ClipboardViewerIgnore`），并支持自定义敏感内容检测（`sensitive.collect_secrets` / `redact_secrets`：自动识别 API Key、私钥、JWT、密码串并打上 `is_sensitive = 1`，在普通列表中脱敏掩码显示）。
   - 按 `capture.order`（默认 `["files", "image", "html", "rtf", "text"]`）读取剪贴板格式，检查 `max_text_mb`（4MB）与 `max_image_mb`（100MB）上限（入库时 `search_text` 截断至前 64 KB）：
     - **图片**：存为 `<DATA_DIR>\media\clipboard_images\<blake3>.png`；若开启了剪贴板图片自动 OCR（`capture.image_ocr = true`），后台异步调用 `orbment-core::OcrEngine`（遵循全局 `[app].ocr_engine_tier` 配置，Stage 4 即内置 `Windows.Media.Ocr` 挡位 1，且不受 `vision` 模块启停影响；Stage 6 接入离线 ONNX 挡位 2）将识别出的文字填入 `search_text`。
     - **HTML / RTF**：在 `raw_payload`（SQLite `BLOB` 列）无损保存原始富文本字节，在 `content` 保存纯文本，`search_text` 存去标签后的可检索文本。
2. **全文检索与分类/分组过滤**：
   - 搜索框查询 `clipboard_items_fts`（`fts5(tokenize='trigram')`）：3 个字符及以上的中英文子串走索引；1~2 字符的短词（中文双字词很常见）回退为 `LIKE`/`INSTR` 扫描。万条级历史下的响应时间以实测为准，目标是输入时无感知延迟。
   - 顶部标签栏还原 EcoPaste 原生分类：**全部、文本、图片、文件、收藏（Star）** + 用户自定义分组（`clipboard_groups`）。
3. **弹窗交互与自动粘贴上屏**：
   - 呼出快捷键（可选接管 `Win+V`，接管时请求 `WH_KEYBOARD_LL` 钩子引用）弹出剪贴板窗口，位置支持**跟随鼠标（`followCursor`）**、**屏幕居中**或**上次位置**；弹窗失去焦点（`WM_ACTIVATE(WA_INACTIVE)`）且未处于固定状态时自动隐藏。
   - **焦点处理与修饰键清理（已定，照 EcoPaste）**：呼出时记录当前前台窗口 `last_active_hwnd`，弹窗激活并接收键盘操作（方向键选条目、打字搜索、空格预览）；粘贴时隐藏弹窗、把焦点还给 `last_active_hwnd`，再发送粘贴。
   - 双击条目（或单击/回车/按 `Ctrl+Shift+数字` 快捷粘贴）：
     1. 将目标条目写回系统剪贴板（写入时附带内部标记格式，避免自己写入的内容被重复入库；若为“粘贴为纯文本”或“文件粘贴为路径”，按转换后格式写入）；
     2. 隐藏弹窗，将焦点归还 `last_active_hwnd`；
     3. 通过 `SendInput` 发送粘贴按键：为避免用户在按下 `Alt+C` 或 `Ctrl+Shift+数字` 后手指尚未完全松开导致目标窗口收到错误的组合键，同时避免单独注入 `Alt` 或 `Win` 抬起触发窗口菜单栏或系统开始菜单，单次 `SendInput` 批次严格按以下顺序构造事件序列：`VK_CONTROL` 按下 -> 当前仍处于物理按下状态的 `Alt` / `Shift` / `Win` 注入 `KEYEVENTF_KEYUP` 抬起（因 `Ctrl` 已先行按下，系统不会将 `Alt`/`Win` 抬起判为单按菜单键） -> `'V'` 按下与抬起 -> `VK_CONTROL` 抬起（若调用前用户原本就物理按着 `Ctrl` 键，则省略最后一步 `VK_CONTROL` 抬起）。
4. **悬停/空格大图与原文预览（`preview`）**：
   - 选中条目按 `Space` 键（`space_enabled = true`）或鼠标悬停达到 `hover_delay_ms`（`500ms`），在侧边弹出完整原图/完整长文本/富文本结构/文件列表预览窗。

## 模块五：MFT 引擎双子——磁盘空间分析（MFT 扫描 + 嵌套树图）、双后端文件搜索与文件解锁（`[file_search]` & `[disk_analyzer]`）

> **已定**：
> 1. 文件搜索（`[file_search]`，默认关闭）与磁盘空间分析（`[disk_analyzer]`，默认启用但仅在打开窗口时按需扫描）共用同一套底层 NTFS `$MFT` 解析与 `USN Journal` 增量引擎。
> 2. 磁盘空间分析采用 **“NTFS `$MFT` 高速扫描底座 + 可下钻嵌套方块图（Nested Treemap）主视图 + 轻量 Top 大文件/扩展名切换页”**，并与模块三的内存可视化共用同一套 Direct2D 嵌套树图组件。

### 5.1 参考基准
- **NTFS `$MFT` 高速扫描与嵌套树图**（底层 `$MFT` 直接解析、分配大小统计、大文件与扩展名排行 + 嵌套带标题容器方块图、层级深度 `+ / -` 调节、双击下钻放大、过滤栏）
- **Everything**（通过其公开 IPC 接入；双模式：内置 MFT 检索 + Everything IPC 桥接）
- **文件占用解锁**（类 LockHunter / PowerToys File Locksmith）

### 5.2 核心 Windows API 与实现原理
1. **自研 NTFS `$MFT` 扫描与 `USN Journal` 增量同步**：
   - 打开 NTFS 卷句柄 `\\.\C:`（或无盘符挂载卷的卷 GUID 路径；需管理员权限，无法提权时回退多线程 `NtQueryDirectoryFile` 逐目录遍历，此时因无 USN 日志权限自动降级为 `OnDemandOnly` 模式）。
   - 使用 `FSCTL_GET_NTFS_VOLUME_DATA` 获取 MFT 布局，**直接读取并解析原始 `$MFT` 记录**（处理扇区 Fixup/USA、扩展记录 `$ATTRIBUTE_LIST`、常驻与非常驻 `$DATA` run list、压缩与稀疏文件的实际分配大小 `Allocated Size`）。建树后自底向上汇总每个文件夹的总大小（同卷硬链接按低 48 位 MFT Record 号去重，只计一次物理大小）、文件数、子目录数与最新修改时间。
   - 扫描前先读取当前卷 `USN Journal` 游标，扫描完成后追平扫描期间产生的新 USN 记录，确保快照一致性；运行时通过 `FSCTL_READ_USN_JOURNAL` 跟进文件增删改与大小变更。
2. **三挡内存驻留策略与 `MftEngine` 引用计数释放规则**：
   - 搜索框与磁盘分析窗口关闭时仅释放各自窗口的 UI；底层共用的 MFT 内存树由 `MftEngine` 按**活动消费者引用计数**管理（打开的搜索窗、打开的磁盘分析窗、`file_search` 启用且处于 `Resident` 模式各计 1 份引用；当 `file_search.backend = "EverythingBridge"` 时搜索模块不持有 MFT 引用）。仅当引用计数归零时，才按以下驻留策略处理（若 `[file_search]` 未启用，最后一个磁盘分析窗口关闭后引用归零即立即释放内存树）：
   - **挡位 1：`Resident`（常驻内存）**：索引随 `file_search` 后台服务一直留在内存里，实时跟进 USN，按键即出结果（不受关窗闲置回收影响）。
   - **挡位 2：`SnapshotIncrement`（闲置释放 + 本地快照增量追平，默认推荐）**：当 `MftEngine` 引用归零且闲置满 `idle_release_seconds`（默认 300 秒）后，将内存树原子落盘为 `<DATA_DIR>\cache\mft_snapshot.bin` 并记录各卷 `last_usn`，随后释放索引内存，后台只留各卷 USN 游标。下次呼出时读入快照（仅做 `O(1)` 头部魔数、版本与文件字节长度检查）并调用 `FSCTL_READ_USN_JOURNAL` 仅追平增量变更；若 USN 日志已被系统截断（`ERROR_JOURNAL_ENTRY_DELETED`）则自动整卷重扫。
   - **挡位 3：`OnDemandOnly`（纯按需重扫，用完即焚）**：平时不占内存也不留快照，打开窗口时才现场扫描，所有使用窗口关闭后立即释放。
3. **文件搜索双后端架构（`FileSearchProvider`）**：
   - **后端 A：内置轻量引擎（默认）**：基于 MFT 紧凑节点数组检索（应用 `included_drives` 与 `exclude_paths` 过滤），支持多关键词分词、前缀/子串、通配符、扩展名过滤（`ext:rs;toml`）、大小/时间过滤（`size:>100mb`），并结合 `file_run_history` 表加权排序。
   - **后端 B：Everything IPC 桥接模式（可选）**：
     - 查找 Everything 的 IPC 窗口（1.4 版为 `EVERYTHING_TASKBAR_NOTIFICATION`，1.5a 版为 `EVERYTHING_TASKBAR_NOTIFICATION_(1.5a)`）；若未运行且配置了 `everything_exe_path`，可自动以 `-startup` 拉起后台进程。
     - 在接收 `WM_COPYDATA` 响应的内部消息窗口上调用 `ChangeWindowMessageFilterEx` 放行 `WM_COPYDATA`（消除管理员 Orbment 接收普通权限 Everything 回复时的 UIPI 拦截），带超时等待返回并在 Orbment 搜索窗中渲染结果。
4. **磁盘空间分析视图**：
   - **主视图：可下钻嵌套方块图（Nested Squarified Treemap）**：
     - 磁盘空间分析完整扫描所选目标卷（不套用文件搜索的 `exclude_paths`，确保目录大小真实准确）；Squarified 矩形切分在后台工作线程计算，主 UI 线程仅通过 Direct2D 硬件加速绘制图元（事件驱动按需重绘，无空转动画）：父目录渲染为带顶部标题栏（显示目录名与分配大小/逻辑大小）的外框容器，内部递归嵌套子目录与大文件色块；
     - 支持顶部**面包屑路径栏**、**`+ / -` 动态调节嵌套展开层级深度（Detail Level）**、**顶部过滤框**（如输入 `*.mp4` 或 `>500MB` 实时过滤树图）、**单击高亮详情**、**双击任意容器方块直接下钻（Zoom In）将该目录作为当前根视图**，以及右键打开资源管理器/终端/移入回收站/查询占用解锁。
   - **辅助切换视图（轻量侧栏或顶部 Tab）**：
     - **Top N 大文件榜（Files View）**：按实际分配大小降序展示当前卷/目录下最大的前 `max_top_files`（默认 1000）个文件；用户主动点击“查找重复文件”时，先按文件字节大小分组筛选同尺寸候选（自动排除同一 MFT Record 的硬链接），仅对同尺寸文件按需读取内容比对；
     - **扩展名统计页（File Types）**：按扩展名汇总空间占比、文件数与对应色块图例。
5. **文件与目录被占用查询与解锁（File Unlock）**：
   - **针对单个文件**：调用 `rstrtmgr.dll` 的 `RmStartSession` -> `RmRegisterResources` -> `RmGetList` 列出占用进程，并结合 `NtQuerySystemInformation(SystemExtendedHandleInformation)` 补充底层文件句柄。
   - **针对文件夹（修正 `RmGetList` 目录限制）**：由于 Windows `RmGetList` 对目录路径直接返回 `ERROR_ACCESS_DENIED`，选中文件夹查询占用时，采用**“后台工作线程扫描系统扩展句柄表匹配该目录路径前缀 + 枚举该目录下被锁子文件分批调用 Restart Manager”**组合策略。
   - 提供“结束占用进程（`TerminateProcess`）”与“强制关闭目标句柄（`DuplicateHandle` + `DUPLICATE_CLOSE_SOURCE`，界面明确提示可能引起目标程序异常）”两种解锁操作。

### 6.2 核心技术实现与 4 项增强能力拆解
1. **多屏截图与智能区域检测**：
   - **抓屏与窗口流式捕获管线**：
     - **单帧与静态捕获**：基于 `Windows.Graphics.Capture`（`IGraphicsCaptureItem` + `Direct3D11CaptureFramePool`）配合 D3D11 Staging Texture 拷贝（不支持 WGC 的环境回退 `BitBlt`）。通过 DXGI `IDXGIOutput6::GetDesc1`（检查 `ColorSpace == DXGI_COLOR_SPACE_RGB_FULL_G2084_NONE_P2020`）结合注册表 `MonitorDataStore\*\HDREnabled` 判定各显示器实时 HDR 状态：SDR 下使用 `DXGI_FORMAT_B8G8R8A8_UNORM (87)`（4 字节/像素，按 `MappedResource.RowPitch` 逐行拷贝），HDR 下自动切换 `DXGI_FORMAT_R16G16B16A16_FLOAT (10)`（8 字节/像素）并执行 HDR -> SDR 色调映射。
     - **流式捕获（用于实时窗口贴图 `Window ROI Pin` 与屏幕录制）**：按需创建**独立的捕获专用 `ID3D11Device`**（与主线程 UI 设备隔离，停止捕获后释放），内部维护 **3 槽位环形 D3D11 Staging Texture 缓冲区** 与原子帧更新标记；实时窗口贴图由捕获设备 Staging 纹理读回 CPU 缓冲后，交由主 UI 线程调用 `UpdateSubresource` 上传至 UI 设备纹理绘制（静态截图同样在捕获完成后将像素读回 CPU 并立即释放捕获会话）。
     - **截图前弹出菜单检测**：截图触发前调用 `GetGUIThreadInfo` 检查当前前台线程 `flags & 0x1C`（`GUI_INMENUMODE | GUI_POPUPMENUMODE | GUI_SYSTEMMENUMODE`），识别活动弹出菜单状态。
   - **窗口与异步 UIAutomation 子控件检测机制**：
     - **桌面窗口预快照**：通过 `EnumDesktopWindows` 枚举顶层窗口，依次过滤：忽略列表中的 HWND、含 `WS_EX_TRANSPARENT (0x20)` 穿透样式的窗口、`!IsWindowVisible` 的窗口、以及 `DwmGetWindowAttribute(hwnd, DWMWA_CLOAKED = 14) != 0` 的窗口（剔除后台挂起的 UWP 应用与其他虚拟桌面的隐形窗口）；使用 `DwmGetWindowAttribute(hwnd, DWMWA_EXTENDED_FRAME_BOUNDS = 9)` 获取不含透明阴影边框的真实可见矩形，并裁去桌面交集外的部分。
     - **异步 MTA 工作线程隔离与 50ms/300ms 降级策略**：
       1. 跨进程 `IUIAutomation::ElementFromPoint` 不在主 UI 线程同步调用，而是运行在独立的 **后台 MTA 探测线程** 中；鼠标移动时 UI 线程立即先用预快照的 `HWND` 矩形高亮渲染，同时向探测线程发送最新坐标并在收到异步探测结果时收缩到子控件选框；
       2. 探测线程在调 UIA 前先用 `IsHungAppWindow(hwnd)` + `SendMessageTimeoutW(hwnd, WM_NULL, 0, 0, SMTO_ABORTIFHUNG | SMTO_BLOCK, 50, &res)` 快速过滤无响应窗口；
       3. 探测线程用 `GetTickCount64()` 记录单次 UIA 耗时：若某窗口单次 UIA 耗时 **`> 300ms`** 或返回无效矩形，立即将该窗口标记为仅用 `HWND / MSAA` 探测，后续鼠标在该窗口内移动不再发起慢速 UIA 请求。
     - 支持按 `Tab` 或滚轮在父子元素层级间切换。
   - 支持**矩形选区**、**圆角矩形**、**自由/多边形选区**以及**预设尺寸/比例选区**（如 3:4、16:9、1:1、视频封面尺寸）。
2. **屏幕取色器与放大镜**：
   - 截图与取色模式下，鼠标旁实时显示像素网格放大镜，显示当前像素颜色与坐标。
   - 支持快捷键切换颜色格式（HEX `#RRGGBB`、RGB、HSL、HSB、CMYK、Oklab、Oklch、CIE Lab、十进制 BGR），支持 `%ReX` 语法的自定义颜色格式模板，以及**复制为色卡贴图**。
3. **矢量标注画布（支持二次编辑与撤消/重做）**：
   - 标注工具：矩形/椭圆、聚光灯、画笔、荧光笔、箭头、折线、放大镜、文本、水印、序号、马赛克、自动马赛克、橡皮擦。工具栏的分组与顺序可自定义。
   - **【增强能力 1：双击箭头/折线添加评论文本】**：
     - 所有的标注图元均作为独立矢量对象保存在画布场景图中（支持随时点击已有图元调整端点、颜色、粗细）。
     - 当用户在已绘制的**箭头**或**折线**上**双击鼠标左键**（且未关闭此功能）时，在该箭头杆部弹出内联文本输入框：
       - 支持输入评论文字，文字嵌入在箭头线段中间（自动留白断开箭头线或带描边背景）；
       - 支持设置文字方向（`Auto` 自动正立 / `Follow` 跟随箭头倾角 / `Flat` 始终水平）、字体、字号、粗体、斜体与描边（`Outline`）；拖动箭头端点时，嵌入文本自动保持在箭头中点同步跟随旋转与移动。
   - **自动马赛克**：选取一个区域或搭配 OCR 文本框检测，自动对画面中的文字块或指定目标批量打码（支持像素格马赛克与高斯模糊两种模式及强度滑块）。
4. **多实例贴图窗口与【增强能力 2：贴图标注时快捷选择文本】**：
   - 支持 4 种贴图载体：**图像贴图**、**纯文本/HTML 便签贴图**、**色卡贴图**、**实时窗口区域贴图**（通过 `Windows.Graphics.Capture` 或 `DwmRegisterThumbnail` 实时映射源窗口局部画面）。
   - **【增强能力 2：贴图标注与查看时快捷选择图片内文本】**：
     - 图像贴图生成后（或在“文本默认可选”开启时 / 双击贴图触发文本选择时），后台运行一次 OCR，把每段文字和字符的包围盒缓存在该贴图实例中（不改动贴图像素）。

     - **识别引擎（已定）**：首次使用 OCR 相关功能时询问用户：用系统自带 OCR（无需下载，中文准确度一般），还是下载高精度离线模型（需另外下载模型文件）。之后可在设置中更改。
   - **贴图窗口底层控制**：
     - 滚轮缩放、Ctrl+滚轮调透明度、缩略图模式、窗口阴影、贴图分组管理、晃动窗口隐藏其他贴图、一键恢复上次关闭的贴图、开机自动恢复未关闭贴图；
     - **无焦点与鼠标穿透**：通过动态位操作修改 `GWL_EXSTYLE (-0x14)` 的 `WS_EX_NOACTIVATE (0x08000000)` 与 `WS_EX_TRANSPARENT (0x20)`（穿透时自动降低不透明度并显示指示边框色）；
     - **工具窗口样式与任务栏图标显隐**：通过切换 `GWL_EXSTYLE` 的 `WS_EX_TOOLWINDOW (0x80)`，以及在需要隐藏任务栏按钮时通过 `SetWindowLongPtrW(hwnd, GWLP_HWNDPARENT, dummyStaticHwnd)` 将顶层贴图窗口的 **Owner** 指向内部隐藏的宿主窗口，控制任务栏/Alt+Tab 显隐行为。
5. **双挡位 OCR（全局配置位于 `[app].ocr_engine_tier`）**：
   - **挡位 1（默认保底）**：`orbment-core` 内置的 `Windows.Media.Ocr` 系统原生引擎，无需额外模型文件。
   - **挡位 2（高精度离线模型）**：通过 `ort`（`load-dynamic`）按需加载 `<DATA_DIR>\models\` 下的 RapidOCR ONNX 模型（支持中英日韩混排、竖排文本、去除多余空格、中英文标点转换），闲置满 `[app].ocr_idle_unload_seconds` 后卸载推理会话。
6. **长截图（垂直与水平滚动拼接 + 回滚自动裁剪）**：
   - **自动滚动双通道**：
     - 通道 A（全局输入模拟）：通过 `SendInput` 发送 `MOUSEEVENTF_WHEEL (0x0800)`（垂直滚动）或 `MOUSEEVENTF_HWHEEL (0x1000)`（水平滚动）；
     - 通道 B（窗口消息定点投递）：通过 `WindowFromPoint` 找到目标滚动窗口，直接向其投递 `PostMessageW(hwnd, WM_MOUSEWHEEL = 0x020A / WM_MOUSEHWHEEL = 0x020E, (( (steps * 120) as i16 as u16 as usize ) << 16), MAKELPARAM(screenX as i16, screenY as i16))`（`WM_MOUSEWHEEL` 的 `lParam` 按 Win32 规范传入有符号**屏幕坐标**）。
   - 每滚动一帧，匹配上下帧的重叠区域并在预览窗中实时拼接；用户**往回滚动**时，自动识别回退位置并裁掉多余部分。
7. **屏幕录制（GIF / MP4 / WebP）与【增强能力 3：录制动图/视频时记录键鼠操作】**：
   - **录制期间自身工具栏防入画**：调用 Win10 2004+ 原生 API `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE = 0x11)`，使录制工具栏、选区高亮框与键鼠回显浮层对用户肉眼正常可见，但在系统录屏/截屏画面中自动隐身，避免隐藏窗口带来的闪烁。
   - **【增强能力 3：多轨分录与回放/导出后期合成架构】**：
     - 普通录制模式并非在录制时把鼠标波纹和按键气泡直接画死在视频画面上，而是将**实时编码的临时视频轨（H.264 关键帧间隔 ≤ 1s 的分段 MP4，避免未压缩原始帧撑爆磁盘）、系统音频轨、麦克风音频轨、鼠标事件轨（记录坐标/点击/滚轮）、键盘按键事件轨（记录按键序列）**按统一的 `QueryPerformanceCounter`（QPC）高精度单调时钟分轨写入临时会话目录；导出完成、用户取消或下次程序启动时自动清理临时会话目录；
     - 停止录制后进入回放与裁剪窗口，用户既可拖动时间轴首尾手柄裁剪片段，也可在回放预览时实时调整：
       - **鼠标可视化**：光标缩放大小、左/右/中键点击波纹颜色、滚轮滚动指示、动画速度、**平滑鼠标移动轨迹**与**简化鼠标动画**；
       - **键盘按键可视化**：在画面角落渲染按键气泡，分别开关**字符键**、**组合键**、**修饰键**与**功能键**，调整字号、文本/背景色、停留时间、连续字符合并上限与历史按键行数；
     - 确认导出时，由合成管线将裁剪后的视频帧、平滑鼠标轨迹波纹、按键气泡与音频混流编码为 **MP4**（Media Foundation H.264）、**GIF** 或 **动图 WebP**（第三方编码库选用 MIT/Apache/BSD 等宽松许可证）；而“快速录制（Quick Recording）”模式则跳过分轨回放与键鼠动画合成，录制结束直接导出 MP4。
8. **【增强能力 4：全局鼠标快捷操作】**：
   - 用户可配置**修饰键（`Ctrl` / `Shift` / `Alt` / `Win` 任意组合；左键手势强制要求至少一个修饰键，防止误触；侧键 `X1`/`X2`、中键可单独使用）+ 鼠标动作**（左/右/中/X1/X2 的单击、双击、拖动及滚轮）。
   - **4 态状态机与“未拖拽时原样重放点击”核心逻辑**：
     - 状态机包含 4 个状态：`0 = WaitModifier` -> `1 = ModifierEntered` -> `2 = MouseButtonPressed` -> `3 = MouseDragging`；钩子回调首先忽略带 `LLMHF_INJECTED` 标记的合成鼠标事件，防止重放事件自我递归。
     - 当修饰键按下进入 `State 1` 后，收到物理鼠标按键按下时检查是否命中已配置的手势：若命中，**先在 `WH_MOUSE_LL` 钩子中返回非零吞掉该次按下事件**（防止接下来拖拽选区时底层窗口文字被误选中），记录按下起始点 `start_pos` 并切入 `State 2`；
     - 在 `State 2` 收到鼠标移动时，若该组合绑定了拖拽手势且当前点与起始点的曼哈顿距离 `> drag_threshold`，切入 `State 3 (MouseDragging)` 并异步拉起区域截图或贴图；
     - 在 `State 2` 收到鼠标松开（移动距离未达拖拽阈值）时：若该组合绑定了单击/双击动作则触发对应动作；若该按键**仅绑定了拖拽手势而未绑定点击动作**，立即重置状态机为 `WaitModifier` 并**将刚才吞掉的鼠标点击原样重放给底层窗口**，使按住 `Ctrl`/`Shift`/`Alt` 在其他软件里做正常单击（如多选文件、跳转链接）照常生效。
   - **全屏与忽略进程检测**：触发前检查目标点所属进程是否在忽略列表中，并通过 `SHQueryUserNotificationState == QUNS_RUNNING_D3D_FULL_SCREEN (3)` 及屏幕对角内缩 `min(w/4, h/4, 8)` 像素的双点 `WindowFromPoint` 同一 HWND 判定是否处于全屏游戏/应用。

## 模块七：桌面小工具集与未来扩展槽（`[utilities]`、`[quick_ask]`、`[hotkey_engine]`）

### 7.1 轻量桌面小工具（统一归属 `[utilities]`，Stage 3 交付）
1. **窗口置顶控制（Window Topmost Controller，`utilities.topmost_hotkey`）**：
   - 支持快捷键将**当前活动窗口**或**当前鼠标指针下方的窗口**（`WindowFromPoint` -> `GetAncestor(hwnd, GA_ROOT = 2)`）检查 `GWL_EXSTYLE & WS_EX_TOPMOST (8)` 后切换 `SetWindowPos(rootHwnd, HWND_TOPMOST / HWND_NOTOPMOST, 0, 0, 0, 0, SWP_NOMOVE | SWP_NOSIZE)`。
   - 当窗口被置顶时，优先尝试 `DwmSetWindowAttribute(hwnd, DWMWA_BORDER_COLOR, &color, sizeof(COLORREF))`；若跨进程调用被拒绝或在不支持该属性的 Win10 系统上，则使用轻量穿透的 `OverlayFloatingWindow` 跟随目标窗口绘制高亮提示边框（或短暂闪烁四角角标）。
2. **独立屏幕取色器（Screen Color Picker，`utilities.color_picker_hotkey`）**：
   - 基础取色放大镜归属 `orbment-ui`，**即使 `vision` 截图贴图模块被禁用，独立取色器依然可正常唤出并复制颜色值**；左键单击按首选格式复制色值到剪贴板，右键切换色值格式（HEX / RGB / HSL / Oklch 等）。当 `vision` 模块已启用时，额外支持在取色时按贴图键直接生成桌面色卡贴图。
3. **系统防休眠 / 保持亮屏开关（Keep Awake / Caffeine，`utilities.keep_awake_*`）**：
   - 通过托盘菜单勾选项或快捷键切换，使用 `PowerCreateRequest` 与 `PowerSetRequest`（设置 `PowerRequestSystemRequired` 与 `PowerRequestDisplayRequired`，无需绑定特定长寿线程，关闭时 `PowerClearRequest`）。
   - 支持设置时长：**始终保持唤醒**、**30 分钟**、**1 小时**、**2 小时**、**直到指定进程退出**（通过等待目标进程 `SYNCHRONIZE` 句柄触发自动恢复）。
4. **外接显示器硬件亮度调节（DDC/CI，`utilities.brightness_hotkey_up/down`）**：
   - 通过 `GetPhysicalMonitorsFromHMONITOR` + `GetMonitorBrightness` / `SetMonitorBrightness` 控制外接显示器硬件亮度（笔记本内屏自动回退 WMI `WmiSetBrightness`），支持快捷键增减与托盘菜单滑块调节；DDC/CI 硬件通信耗时较长（数十毫秒），一律放在后台工作线程带去抖（Debounce）执行，并在收到 `WM_DISPLAYCHANGE` 时调用 `DestroyPhysicalMonitors` 重新枚举显示器句柄。
### 7.2 预留扩展槽一：截图/选中文字快速呼出 LLM 小窗（`orbment-quickask`）
> **阶段定位**：最后阶段的扩展，现阶段只在设计上留位置（ActionBus 的动作都带参数说明，可直接转成 LLM 工具定义；配置节 `[quick_ask]`）。不做完整的 Agent Harness，只做**带上下文的快速提问 + 调用内部 `ActionBus` 工具**。LLM 可调用的动作同样遵守 01 §6.3 的高风险动作开关。

1. **触发与上下文自动采集管道（`QuickContextCapture`）**：
   - **选中文字后按快捷键**：先读取当前剪贴板快照 -> 发送模拟 `Ctrl+C` 或通过 `UIAutomation` `ITextPattern::GetSelection` 获取当前选中文本 -> 恢复原剪贴板内容（这次模拟复制不能被剪贴板历史记录下来） -> 在鼠标旁弹出极简对话小窗，自动附带所选文本与来源软件窗口标题。
   - **截图工具栏一键“问 AI”**：在 `orbment-vision` 截图选区工具栏预留一个按钮，点击后直接将当前框选区域的图片（或自动 OCR 后的文本 + 缩略图）传入同一个极简对话小窗。
2. **流式提问与工具箱自控（Tool Calling -> `ActionBus`）**：
   - 使用标准 OpenAI / Anthropic 兼容 HTTP SSE 流式接口（支持配置自定义 Base URL、API Key、Model 与预设 Prompt 快捷指令，如“解释代码”“总结要点”“执行工具箱动作”）。API Key 不明文写入 `config.toml`（该文件可能被外部直接读取），存入 Windows 凭据管理器。
   - 将 `orbment-core::ActionBus` 中注册的工具 Schema 直接作为 `tools` 暴露给该 LLM 会话——用户可以在小窗里直接说“把刚才截的这张图贴到屏幕右上角并把当前窗口置顶”或“帮我把占用 8080 端口的进程杀掉”，LLM 直接调用内部 `ActionBus` 完成操作。

### 7.3 预留扩展槽二：通用热键映射引擎（`[hotkey_engine]`）
- 依托 `orbment-ui` 已有的按需 `RegisterHotKey` + `WH_KEYBOARD_LL` / `WH_MOUSE_LL` 调度器，预留通用的规则表 `Vec<HotkeyRule>`：
  - **触发条件（Trigger）**：按键组合、物理单键（如 `Volume_Mute`）、双击修饰键、特定进程前台条件（`active_process_filter`）；
  - **执行动作（Action）**：映射发送另一组按键（`SendInput`）、运行外部程序/脚本、或触发 `ActionBus` 内的任意 Orbment 内置动作。
