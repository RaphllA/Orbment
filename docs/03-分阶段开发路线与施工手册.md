# 03 - Orbment（导力匣）分阶段开发路线与施工手册

本文档是面向编码阶段的施工手册：历史归档草稿的取舍边界、各阶段的开发顺序、每个阶段要落地的模块、验证方法，以及交给用户日常试用的验收标准。架构与模块细节分别见 01、02。

## 2. 总体分阶段路线

每个阶段结束时都产出一个可编译运行的 `orbment.exe`，并能替掉至少一个旧软件给用户日常试用。

| 阶段 | 内容 | 试用目标 | 阶段内核实事项 |
| :--- | :--- | :--- | :--- |
| **Stage 1** | 底座 + 音频基础切换与旋钮映射 + 任务栏网速 | 退掉旋钮 AHK 脚本；日常基础播放切换替代 SoundSwitch；任务栏网速与 TrafficMonitor 并排对照 | 只用 Direct2D 微窗通道，不依赖面板 UI 框架 |
| **Stage 2** | 设置中心 + MCP/CLI + 音频与监控补全（含温度） | 完整退掉 SoundSwitch 与 TrafficMonitor | 核实本机 Win10/11 版本对应的 `IAudioPolicyConfigFactory` IID、TrafficMonitor 皮肤格式（`skin.ini`/`skin.xml`）及管理员窗口下 OLE 富格式拖放行为 |
| **Stage 3** | 内存清理/可下钻嵌套内存树图 + 残留进程清理 + 端口快查 + 小工具（置顶、独立取色、防休眠、显示器亮度） | 退掉 Mem Reduct | 对照 Mem Reduct 最新源码核对清理区域常量；核实跨进程 `DWMWA_BORDER_COLOR` 与穿透边框浮层回退 |
| **Stage 4** | 剪贴板（含 `orbment-core` 系统原生图片 OCR 挡位 1）+ `orbment-importer` | 迁入旧剪贴板历史与配置，退掉 EcoPaste | 核实剪贴板粘贴焦点归还时序与修饰键释放批次 |
| **Stage 5** | MFT 扫描 + 嵌套树图磁盘分析 + 文件解锁 + 文件搜索（内置三挡 + Everything 桥接） | 独立完成磁盘分析与文件搜索 | 实测三挡驻留内存与快照增量恢复耗时 |
| **Stage 6** | 视觉模块（独立窗口路径 + 离线高精度 OCR 挡位 2 + 核心标注贴图能力 + 录屏合成）+ 快速 LLM 提问小窗 | 独立完成截图、贴图与录屏 | 实测多屏异构 DPI 截图遮罩与分轨录屏合成 |

> **注**：通用热键映射引擎（`[hotkey_engine]`）按需求仅在配置模型与钩子调度器中预留位置，不进入 Stage 1~6 施工范围。

## 3. Stage 1：底座 + 音频旋钮切换 + 任务栏网速

这是第一个能给用户日常试用的版本。刻意做小：只用 Direct2D 绘制的常驻微窗口，没有设置界面（配置写在 `config.toml`，常用开关放托盘菜单），不包含强依赖管理员权限的业务模块（如 MFT、内存清理），但落地 `asInvoker` 清单按需提权与计划任务最高权限自启底座。

### 3.1 涉及 Crate 与模块
1. **`crates/orbment-core`**
   - `config.rs`：基于 `toml_edit` 实现 `OrbmentConfig`（一次性定义全部顶层配置节结构体，缺失键在内存中填原软件出厂默认，写回时仅持久化用户/导入器修改过的键，保留未知键、注释与节顺序）与原子落盘（写 `.tmp` 后 `rename`）；文件被手改后可重新加载。
   - `lifecycle.rs`：`OrbmentModule` trait、后台服务（`ServiceState`，含 `Unavailable`）与前台视图（`UiSurfaceState`）双轨解耦状态机（01 §3.1）。
   - `action_bus.rs`：动作注册表与 JSON 参数分发（命名规则见 01 §6.1）。Stage 1 先接快捷键和托盘菜单两个入口。
   - `single_instance.rs`：按 01 §2.2 实现“先 `OpenMutexW(SYNCHRONIZE)` 检重（已存在则发送 `RegisterWindowMessageW("Orbment.Activate")` 唤起并直接退出，不弹 UAC）-> 未运行且非管理员则 `ShellExecuteExW("runas")` 提权重启 -> 主实例 `CreateMutexW` 持锁”。
   - `autostart.rs`：内嵌 Manifest（`asInvoker` + `PerMonitorV2` + Win10/11 `supportedOS` GUID），以及计划任务“以最高权限运行”的开机自启开关（启动时校验任务内路径，关闭时删除计划任务，见 01 §2.2）。
   - `i18n.rs`：界面文字从语言资源文件加载，Stage 1 只有简体中文（01 §2.1）。
   - `logging.rs`：`tracing` 按天滚动日志（01 §2.1）。
   - `diag.rs`：模块与进程诊断数据（01 §8），Stage 1 先通过托盘菜单“诊断信息”导出 JSON。
2. **`crates/orbment-ui`**
   - `event_loop.rs`：主消息循环（按需为 `HiddenIdlePending` 窗口挂载最近到期的一次性 `SetTimer`，无待回收窗口时停表），启动时对主消息/托盘窗口调用 `ChangeWindowMessageFilterEx` 放行 `RegisterWindowMessageW("TaskbarCreated")` 与 `RegisterWindowMessageW("Orbment.Activate")`，处理 `WM_HOTKEY`、`TaskbarCreated`、`Orbment.Activate`、托盘消息与跨线程唤醒消息。
   - `hotkeys.rs`：`RegisterHotKey` 注册与冲突提示（01 §3.3，通知统一走 `Shell_NotifyIconW` 的 `NIF_INFO`）。
   - `hook_thread.rs`：低级键鼠钩子专用线程，按引用计数挂载/卸载，忽略带注入标记的合成输入（01 §2.3）。
   - `d2d_context.rs`：主线程共享 UI `ID3D11Device` + Direct2D / DirectWrite 渲染器，以及每窗口独立的呈现目标管理与事件驱动按需重绘（空闲时 0 FPS）。
   - `tray.rs`：单一主托盘图标与按已启用模块动态显隐的右键菜单（01 §4.1）。
   - `windows/`：`TaskbarChildWindow`（D2D DC/透明色键或 Layered 目标）、`OverlayFloatingWindow`（Stage 1 用于 OSD 横幅，`UpdateLayeredWindow`）。
3. **`crates/orbment-audio`**
   - `enumerator.rs`：`IMMDeviceEnumerator` 设备枚举与 `IMMNotificationClient` 热插拔监听。
   - `policy_config.rs`：`IPolicyConfig` 切换默认播放/录音/通信设备。
   - `cycler.rs`：在已选设备间轮换（对齐 SoundSwitch 的切换模式）。
   - `knob.rs`：在钩子线程注册 `VK_VOLUME_MUTE` 物理按键拦截，投递 `audio.switch_playback`（默认关闭）。
   - `osd.rs`：切换横幅。
4. **`crates/orbment-monitor`**
   - `sampler.rs`：`GetIfTable2` 网速采样（自动选择 / 全部 / 指定网卡）、`GetSystemTimes` CPU 占用、`GlobalMemoryStatusEx` 内存占用。
   - `taskbar_wnd.rs`：照 TrafficMonitor 的 `TaskBarDlg.cpp` / `TaskbarHelper` 实现任务栏嵌入（01 §4），显示网速、CPU、内存，字体、配色、前缀文本可配。
5. **`crates/orbment-app`**：`orbment.exe` 入口。

不在 Stage 1 的：设置界面、MCP/命名管道、数据库、Profile 与按应用路由、温度、桌面悬浮窗、皮肤、流量历史。

### 3.2 Stage 1 验收与试用标准
- **编译与测试**：`cargo build --release` 无警告；设备轮换逻辑、网速计算、配置读写有单元测试并通过。
- **真机试用**（在开发者电脑上）：
  1. 在设置文件里开启旋钮拦截后，按键盘音量旋钮能在两个已选播放设备间切换，并弹出 OSD 横幅；关闭拦截后静音键恢复原样。
  2. 任务栏嵌入窗口正常显示网速、CPU、内存，数值与 TrafficMonitor 并排对照基本一致；全屏游戏/视频时不闪烁、不抢焦点；重启 `explorer.exe` 后自动重新挂上。
  3. 开启开机自启后重启电脑，Orbment 自动以管理员身份启动，不弹 UAC。
- **资源记录**：用任务管理器 / Process Explorer 记录只开音频与任务栏监控时的常驻内存（工作集与私有内存），作为后续阶段的基线。目标是明显低于 SoundSwitch + TrafficMonitor 之和，具体数字以实测为准，不预设。

## 4. Stage 2：设置中心 + MCP/CLI + 音频与监控补全

已定：面板统一使用共享 `D3D11 + Direct2D` 设备上的 `egui` 后端（01 §2.1），入口遵循“托盘未启用模块隐身 + 设置中心左侧导航直带模块总开关”（01 §4.1）；硬件温度采用单进程纯 Rust 原生读取（显卡 NVML/ADL + 硬盘系统 IOCTL/SMART + CPU PawnIO，主板温度第一版不做，见 02 模块二）。

### 4.1 涉及模块
1. **`orbment-ui`**：基于主线程共享 `D3D11 + Direct2D` 设备的 `MainHostWindow`（独立 SwapChain/RTV + 事件驱动按需重绘的 `egui` D3D11 网格渲染器 + 共享只读字体缓冲 + 共享 `IMM32` 中文输入法跟随组件）与设置中心（左侧导航栏直带模块总开关）；文件拖入的消息放行（01 §2.2）。
2. **`orbment-core`**：`ipc.rs` 命名管道服务端（显式 SDDL 授予当前 `TokenUser` 读写权限 + 中等完整性标签 `S:(ML;;NW;;;ME)` + `PIPE_REJECT_REMOTE_CLIENTS`，使非提权 `mcp`/`cli` 客户端可正常连接管理员主进程；`app.config_set` 拦截对受保护配置项的修改，见 01 §6.2）；`db.rs` 初始化 `orbment.db`（WAL、`journal_size_limit`，读取 `user_version` 并在单事务内按版本迁移后更新 `user_version`）。
3. **`orbment-mcp` / `orbment-app`**：`orbment.exe mcp`（无状态不提权 stdio 转发到命名管道，工具名将 `.` 映射为 `_`）、`orbment.exe cli`；开放 `app.*`、`audio.*`、`monitor.*` MCP 工具（01 §6.3）。
4. **`orbment-audio`**：录音设备切换、麦克风静音与常驻角标、`app_routing.rs`（按应用路由，分系统版本处理 IID）、Profile、各类通知方式、主托盘图标联动，对照 02 模块一与 SoundSwitch 补齐设置项。
5. **`orbment-monitor`**：`floating_wnd.rs` 桌面悬浮窗（穿透、吸附、全屏隐藏、TrafficMonitor `skin.ini`/`skin.xml` 皮肤）；`sensors.rs` 后台纯 Rust 温度/频率读取（勾选时才加载 NVML/ADL 或访问 PawnIO 驱动，硬盘温度低频轮询并跳过休眠盘，不做主板温度）；`history.rs` 每日流量统计与告警；缓存式 GPU/硬盘占用；对照 02 模块二与 TrafficMonitor 补齐设置项。

### 4.2 验收
- 设置中心能改 Stage 1/2 所有模块的设置，改动即时生效并写回 `config.toml`；对照 02 模块一、二及原软件设置界面核对设置项覆盖。
- 普通权限终端运行 `orbment.exe mcp` 能正常连接管理员主进程，列出设备、切换设备、读取监控快照。
- 悬浮窗、温度、流量历史与 TrafficMonitor 对照一致后，退掉 SoundSwitch 与 TrafficMonitor。
- 关闭设置中心后，按 01 §2.1 的选型结论如实记录内存回落情况。

### 4.3 Stage 2 实测记录（2026-10-21）
- 构建检查：`cargo test --workspace` 共 41 项测试通过；`cargo clippy --workspace --all-targets -- -D warnings` 与 `cargo build --release` 通过，无编译警告。
- 普通权限隔离数据目录冒烟：主进程使用 `--no-elevate`；CLI `app.status` / `diag`、MCP 初始化和 10 项 `tools/list`、`audio_list_devices` / `monitor_snapshot` 调用通过。`mcp.allow_memory_clean`、`monitor.double_click_exe`、`quick_ask.enabled` 和未授权 `memory.auto_clean_threshold_enabled` 写入均被拒绝；普通配置热更新、TOML 写回及音频/监控即时启停通过。独立 MCP 进程未加载 D3D11、D2D、DirectWrite、DXGI 或 D3DCompiler DLL。
- 数据与界面：确认 SQLite `user_version = 1`、WAL 模式、完整表结构和每日流量落库；设置中心打开、中文 `WM_CHAR` / IME 取消路径、关闭销毁以及任务栏独立配色和状态条绘制通过冒烟。正常消息循环退出成功，后台服务停止，日志无告警。

- 硬件样本：获得 CPU 频率、GPU/显存占用、硬盘活动率以及 GPU/硬盘温度；普通令牌读取 PawnIO CPU 温度返回明确的管理员权限提示。**尚未完成管理员主进程与普通客户端的跨完整性实测、PawnIO 管理员温度读取、实际设备切换/应用路由、真实输入法候选框交互及与 SoundSwitch / TrafficMonitor 的逐项实机对照**；这些项目不能用本次同完整性冒烟替代。

## 5. Stage 3：内存、端口与小工具

### 5.1 涉及模块
1. **`orbment-analyzer::memory`**：`memory_clean.rs`（区域列表以 Mem Reduct 源码为准）、阈值/定时自动清理；`memory_treemap.rs`（实现后台 Squarified 布局计算 + Direct2D **可下钻嵌套方块图组件**，第一层物理内存近似概览，第二层进程家族带标题外框嵌套，第三层双击下钻 `VirtualQueryEx` 单进程虚拟内存）。
2. **`orbment-analyzer::reaper`**：残留进程清理（02 模块三第 4 项）——家族登记（含从树图右键预填）、残留判定、预览确认、礼貌关闭与单独确认的强制结束；树图上标出残留家族。
3. **`orbment-analyzer::port`**：`GetExtendedTcpTable` / `GetExtendedUdpTable` 端口快查与结束进程。
4. **`orbment-ui::utilities`（调用 `orbment-core` 纯系统函数）**：统一归入 `[utilities]` 的 4 项小工具（`OrbmentModule` 实现位于 `orbment-ui`）——窗口置顶（含穿透边框浮层回退）、独立屏幕取色器（复制色值不依赖 `vision` 模块，色卡贴图联动到 Stage 6 再接）、防休眠（`PowerCreateRequest` / `PowerSetRequest`，支持倒计时或等待指定进程退出）、后台线程去抖的 DDC/CI 外接显示器亮度与 WMI 内屏回退（监听 `WM_DISPLAYCHANGE` 刷新句柄）。
5. **MCP**：开放 `memory.*` 与 `utilities.*` 工具（01 §6.3），落地高风险动作（`memory.clean`、`memory.process_kill`、`memory.process_reap`）的逐项允许开关，默认不允许。

### 5.2 验收
- 内存清理各区域释放量与 Mem Reduct 对照合理，核对 02 模块三设置项后退掉 Mem Reduct。
- 输入端口号能列出占用进程并结束。
- 登记一个家族后关掉其主程序，内存面板能列出残留的帮手进程，确认后礼貌关闭；主程序还开着时不列出任何进程；预览后主程序又被打开时，执行会中止。
- 置顶、取色、防休眠、亮度都能从托盘或快捷键使用。

### 5.3 Stage 3 实测记录（2026-10-21）

## 9. 每个阶段合入前的检查

1. **未启用模块不产生后台开销，启用未开窗时不产生 UI 开销**：在 `config.toml` 或设置中心把某模块设为 `enabled = false`（包括运行中动态关闭）后，确认该模块无工作线程、系统钩子和额外内存；当模块处于 `ServiceState::Running` 但未打开窗口（`UiSurfaceState::Unloaded`）时，确认未创建可视 UI 窗口与呈现目标（仅允许剪贴板等后台事件监听所需的隐藏消息接收窗口），且窗口打开静止时帧率为 0 FPS（事件驱动按需重绘）。
2. **窗口资源独立隔离与闲置回收**：打开再关闭剪贴板弹窗、设置中心、磁盘树图、内存树图或单张贴图，确认其他正在显示的窗口不受影响；等闲置计时到期后记录私有内存回落情况，并检查 GDI/User 句柄与每窗口呈现目标/纹理资源无泄漏。
3. **拒绝过度防御、冗余校验与无谓哈希开销（60/95 轻量铁律）**：仅在外部输入边界（配置文件解析、IPC/MCP 权限边界、损坏快照头）做一次直接校验，内部数据结构信任类型不变量；**严禁在代码中塞入无意义的防御性包装、冗余状态复核、对本地大缓存或 DLL 的 SHA-256/哈希比对，也不要写凑数的形式化测试**，只为关键纯逻辑（配置读写、设备轮换、网速计算、FTS 查询、树图切分）编写直接有效的单元测试。
4. **不硬编码个人环境**：代码中不得出现具体电脑的路径（如 `C:\Users\<用户名>`、`D:\ECOPASTE`）；在一个空白目录放上 `portable.flag` 启动 `orbment.exe`，所有已完成的模块都能生成默认配置与空库并正常工作。默认值与原软件出厂默认一致。
5. **界面文字不写死**：代码中不出现直接写给用户看的中文字符串，全部来自语言资源文件。
6. **`orbment-importer` 可剥离**：从 workspace `members` 中移除 `orbment-importer` 后，`cargo check -p orbment-app` 能通过。
